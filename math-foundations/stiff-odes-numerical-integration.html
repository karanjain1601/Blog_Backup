Stiff ODEs and Numerical Integration

Stiff ODEs arise when components evolve on vastly different timescales, forcing explicit integrators to take tiny steps for stability even when the solution of interest is slow. In ML they appear in neural ODEs, gradient flow analysis, and (implicitly) in RNN training.

What Makes an ODE Stiff

For $dy/dt = f(y)$ with Jacobian $J = \partial f/\partial y$, the stiffness ratio is:

$$S = \frac{\max|\text{Re}(\lambda_i)|}{\min|\text{Re}(\lambda_i)|}$$

Explicit methods require $h < 2/|\lambda_{\max}|$. For $S=10^6$, solving 1 unit of slow-timescale time requires $\sim S$ steps — extremely expensive.

Explicit vs Implicit Methods

Method Stability Steps (stiff) Cost/step
Forward Euler Conditionally stable $O(S)$ 1 eval
RK4 Explicit $O(S)$ 4 evals
Backward Euler A-stable (unconditional) $O(1)$ 1 eval + Newton
Radau IIA (order 5) L-stable $O(1)$ 3 evals + Newton

Implicit methods require solving $y_{n+1} - h\,f(y_{n+1}) = y_n$ via Newton iteration at each step — expensive per step but allow arbitrarily large $h$ for stiff problems.

import torch
from torchdiffeq import odeint_adjoint

class ODEFunc(torch.nn.Module):
    def __init__(self, dim=64):
        super().__init__()
        self.net = torch.nn.Sequential(
            torch.nn.Linear(dim, dim), torch.nn.Tanh(),
            torch.nn.Linear(dim, dim))
    def forward(self, t, z): return self.net(z)

class NeuralODE(torch.nn.Module):
    def __init__(self, dim=64):
        super().__init__()
        self.f  = ODEFunc(dim)
        self.out = torch.nn.Linear(dim, 10)
    def forward(self, x):
        t  = torch.tensor([0., 1.])
        z1 = odeint_adjoint(self.f, x, t, method='dopri5')[-1]
        return self.out(z1)

# Stiff problem: use implicit Radau solver
from scipy.integrate import solve_ivp
def robertson(t, y):
    return [-0.04*y[0]+1e4*y[1]*y[2],
             0.04*y[0]-1e4*y[1]*y[2]-3e7*y[1]**2,
             3e7*y[1]**2]
sol = solve_ivp(robertson, [0,1e11], [1.,0.,0.], method='Radau', rtol=1e-8)

Neural ODEs

$$\frac{dz(t)}{dt} = f_\theta(z(t), t), \quad z(T) = z(0) + \int_0^T f_\theta(z,t)\,dt$$

ResNet is Forward Euler discretisation with $h=1$: $z_{n+1} = z_n + f_\theta(z_n)$.

Benefits: constant-memory training (adjoint method), adaptive compute, exact log-likelihood for normalising flows. Limitations: slower training, stiff dynamics require implicit solvers.

Adjoint Sensitivity Method

Gradient via backward-in-time co-state $a(t) = \partial L/\partial z(t)$:

$$\frac{da}{dt} = -a(t)^\top \frac{\partial f}{\partial z}\Big|_{z(t)}, \qquad \frac{dL}{d\theta} = -\int_0^T a(t)^\top \frac{\partial f}{\partial \theta}\,dt$$

Memory: $O(1)$ vs $O(T)$ for direct backprop through solver steps. Tradeoff: recomputes $z(t)$ backwards, introducing additional numerical error.

Stiffness in RNN Training

Hidden state recurrence $h_t = \sigma(Wh_{t-1} + Ux_t)$: if $\kappa(W)\gg 1$, gradients explode or vanish through $W^T$. This is the stiffness problem applied to discrete dynamics. Solutions: LSTM/GRU gating (adaptive effective step size), gradient clipping, orthogonal weight initialisation.

Method Order A-stable? Use case
Forward Euler 1 No Toy problems
RK4 4 No Non-stiff, moderate accuracy
Dormand-Prince RK45 4–5 No (adaptive $h$) Non-stiff neural ODEs
Backward Euler 1 Yes Stiff, low accuracy
Radau IIA 5 Yes (L-stable) Stiff, high accuracy

TIP: Neural ODE Practical Recommendations For classification: use dopri5 (RK45). For stiff dynamics or normalising flows: use Radau or SDIRK. Training tolerances rtol=1e-3, atol=1e-4 are usually sufficient; tighten for evaluation. Use odeint_adjoint for memory efficiency.

WARNING: Adjoint Method Can Be Less Numerically Accurate The adjoint integrates backwards, recomputing $z(t)$ from $z(T)$. For chaotic or stiff dynamics, backwards integration can be unstable. Checkpointing (saving states at intervals) is a memory-accuracy tradeoff — available via adjoint_params in torchdiffeq.
