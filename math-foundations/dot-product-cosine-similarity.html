Dot Product and Cosine Similarity

The dot product is the fundamental inner operation of linear algebra — it measures alignment between vectors. Its normalized form, cosine similarity, is the workhorse of modern embedding-based ML: word similarity, sentence retrieval, image-text matching, and the attention mechanism all reduce to dot products at their core.

Algebraic and Geometric Definitions

For vectors u, v ∈ ℝⁿ, the dot product has two equivalent definitions:

Algebraic: u · v = Σᵢ uᵢvᵢ = u₁v₁ + u₂v₂ + ... + uₙvₙ

Geometric: u · v = ||u||₂ · ||v||₂ · cos(θ)

where θ is the angle between u and v. The dot product is largest when vectors are parallel (θ=0°, cos=1), zero when orthogonal (θ=90°, cos=0), and negative when anti-parallel (θ=180°, cos=-1).

import numpy as np

u = np.array([1., 2., 3.])
v = np.array([4., 0., -1.])

# Algebraic: element-wise product sum
dot_alg = np.sum(u * v)         # 1*4 + 2*0 + 3*(-1) = 1
print('Algebraic dot:', dot_alg)
dot_builtin = np.dot(u, v)      # same
print('np.dot:', dot_builtin)

# Geometric: via angle
cos_theta = np.dot(u, v) / (np.linalg.norm(u) * np.linalg.norm(v))
theta_deg = np.degrees(np.arccos(np.clip(cos_theta, -1, 1)))
print(f'Angle: {theta_deg:.1f} degrees')
print(f'cos(theta): {cos_theta:.4f}')

Cosine Similarity: Scale-Invariant Alignment

Cosine similarity is the normalized dot product:

cos_sim(u, v) = (u · v) / (||u|| · ||v||)

Dividing by the magnitudes removes the effect of scale, measuring only the direction of the vectors. Two vectors pointing in the same direction have cosine similarity 1.0 regardless of their lengths. Cosine similarity ranges from -1 (opposite) to 0 (orthogonal) to +1 (same direction). This is crucial for embedding spaces where embedding magnitudes encode frequency or confidence rather than semantic content.

import numpy as np

def cosine(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

king   = np.array([0.8, 0.3, -0.1, 0.6])
queen  = np.array([0.7, 0.4,  0.2, 0.5])
apple  = np.array([-0.5, 0.8, 0.3, -0.2])

print(f'king-queen: {cosine(king, queen):.4f}')  # high
print(f'king-apple: {cosine(king, apple):.4f}')  # low

# Efficient batch cosine via normalized dot product
vectors = np.stack([king, queen, apple])          # (3, 4)
normed  = vectors / np.linalg.norm(vectors, axis=1, keepdims=True)
sim_matrix = normed @ normed.T                    # (3, 3)
print('Similarity matrix:\n', np.round(sim_matrix, 3))

Embeddings: word2vec, CLIP, and Sentence Models

Modern embedding models train to place semantically similar items close together in a high-dimensional space where closeness is measured by cosine similarity:

  • word2vec / GloVe: Word embeddings where cosine similarity correlates with semantic relatedness. The 'king - man + woman ≈ queen' analogy works because vector arithmetic corresponds to concept composition in the trained space.
  • CLIP (Contrastive Language-Image Pretraining): Image and text encoders trained so matched image-text pairs have cosine similarity ~1.0 and unmatched pairs ~0.0. Zero-shot classification is done by comparing image embeddings to text embeddings of class names.
  • SBERT: Sentence encoder where cosine similarity > 0.9 indicates semantic equivalence, < 0.5 indicates unrelatedness.

The Dot Product in Transformer Attention

The core of transformer attention is scaled dot-product attention:

Attention(Q, K, V) = softmax(QKᵀ / √d_k) V

The matrix product QKᵀ (shape: seq_len × seq_len) computes pairwise dot products between all query vectors and all key vectors. Entry [i,j] measures how much token i should attend to token j. Dividing by √d_k prevents the dot products from growing O(d_k) in magnitude, which would push softmax into saturation with near-zero gradients.

The softmax converts scores to a probability distribution over positions, and the weighted sum softmax(·)V aggregates value vectors. In multi-head attention, h independent dot-product attentions run in parallel with different Q/K/V projections, each learning different types of token relationships.

import torch, math
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    """Vanilla attention: O(T^2 * d_k) — the core of transformers."""
    d_k = Q.size(-1)
    # scores[i,j] = how much query i attends to key j
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)  # (..., T_q, T_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = F.softmax(scores, dim=-1)   # normalize across keys
    return weights @ V                     # (..., T_q, d_v)

B, T, d_k = 2, 10, 64
Q = torch.randn(B, T, d_k)
K = torch.randn(B, T, d_k)
V = torch.randn(B, T, d_k)
out = scaled_dot_product_attention(Q, K, V)
print('Attention output:', out.shape)  # (2, 10, 64)

Bilinear Products and Inner Product Spaces

A bilinear form generalizes the dot product: B(u, v) = uᵀAv for a matrix A. When A = I, this is the standard dot product. When A = Σ⁻¹ (inverse covariance), this gives the Mahalanobis distance, which accounts for feature correlations and scales.

An inner product space is a vector space with an inner product ⟨·,·⟩ satisfying: 1. Symmetry: ⟨u,v⟩ = ⟨v,u⟩ 2. Linearity in first argument: ⟨αu+βw, v⟩ = α⟨u,v⟩ + β⟨w,v⟩ 3. Positive-definiteness: ⟨u,u⟩ > 0 for u ≠ 0

The Cauchy-Schwarz inequality |⟨u,v⟩| ≤ ||u|| · ||v|| holds in any inner product space — this is precisely why |cos θ| ≤ 1.

Nearest Neighbor Search in Embedding Spaces

Retrieval tasks reduce to finding the database vector most similar (by cosine or dot product) to a query. For millions of vectors, exact search is O(n·d) — too slow. Approximate Nearest Neighbor (ANN) libraries make this tractable:

  • FAISS (Meta): Product quantization + inverted file index. Best for large-scale CPU or GPU search.
  • ScaNN (Google): Learned quantization optimized for MIPS (Maximum Inner Product Search).
  • HNSW: Graph-based, best recall-per-query tradeoff for in-memory search.

These power Retrieval-Augmented Generation (RAG) systems, where a user query is embedded and the top-k similar document chunks are retrieved as context for the language model.

[TIP] Normalize Before Indexing for Cosine Search

To use FAISS (or similar) for cosine similarity: L2-normalize all vectors to unit length before indexing. Then cosine similarity equals the dot product (u·v = cos θ when ||u||=||v||=1). Use IndexFlatIP (inner product index) which is faster than computing norms on-the-fly. At query time, normalize the query vector too before searching.

[INFO] Dot Product vs Cosine in Neural Networks

Attention mechanisms use raw dot products (not cosine similarity) because the magnitudes of Q and K vectors carry information the model has learned. Explicitly normalizing to unit length before dot products can hurt performance. However, for retrieval over static embedding databases, cosine similarity (normalized dot product) is preferred to remove scale confounds from different encoders or embedding dimensions.
