Perplexity — LLM Evaluation Metric

Perplexity is the standard intrinsic evaluation metric for language models. It answers: on average, how many equally likely choices does the model believe it has at each token position? A model that perfectly predicts every token has PPL=1; a model equivalent to a uniform distribution over a vocabulary of size V has PPL=V.

Information-Theoretic Definition

Given a test corpus (x₁, x₂, ..., x_N), perplexity is defined as:

PPL = exp(H(p_true, p_model)) = exp(-(1/N) Σₜ log p_model(xₜ | x<t))

where the log is natural (for nats) or log₂ (for bits). In bits:

PPL = 2^{(-(1/N) Σₜ log₂ p_model(xₜ | x<t))}

This is the geometric mean of per-token inverse probabilities:

PPL = (Π_{t=1}^{N} 1/p_model(xₜ|x<t))^{1/N}

The geometric mean makes PPL sensitive to low-probability predictions — a single very wrong prediction has an outsized effect.

Branching Factor Interpretation: If a model always assigns equal probability to PPL tokens at each step, it achieves exactly that perplexity. PPL=20 means the model is as uncertain as someone choosing uniformly among 20 options at every step. GPT-2 achieves ~29 PPL on WikiText-103; GPT-4 achieves <10 on the same benchmark.

Stride-Based Perplexity Computation

For documents longer than the model's context window, naive chunking creates boundary artifacts: the model has no context at the start of each chunk and assigns lower probabilities than it would with full context. The solution is a sliding window with stride < context_length, scoring only the new (non-overlapping) tokens at each step.

import torch
import numpy as np
from transformers import AutoTokenizer, AutoModelForCausalLM
from typing import Union

def stride_perplexity(
    text: str,
    model_name: str = "gpt2",
    stride: int = 512,
    device: str = "cpu"
) -> float:
    """Compute perplexity using sliding window to handle long documents.

    The stride controls the overlap. A stride equal to max_length gives
    non-overlapping chunks (fast but boundary artifacts). Smaller stride
    gives more accurate estimates at higher compute cost.

    Args:
        text: Input text to evaluate.
        model_name: HuggingFace model name.
        stride: Number of new tokens scored per window.
        device: 'cpu' or 'cuda'.
    Returns:
        Perplexity (lower is better).
    """
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(model_name).to(device)
    model.eval()
    max_length = model.config.n_positions  # context window size

    encodings = tokenizer(text, return_tensors="pt")
    input_ids = encodings.input_ids.to(device)  # shape (1, T)
    T = input_ids.shape[1]

    nlls = []  # negative log-likelihoods per token
    prev_end = 0

    for begin in range(0, T, stride):
        end = min(begin + max_length, T)
        # Tokens we'll actually score (avoid re-scoring old tokens)
        target_begin = max(begin, prev_end)
        if target_begin >= end:
            break

        chunk = input_ids[:, begin:end]          # input to model
        target_len = end - target_begin

        # Create label: -100 for context tokens (ignored in loss), real IDs for target
        labels = chunk.clone()
        labels[:, :target_begin - begin] = -100

        with torch.no_grad():
            outputs = model(chunk, labels=labels)
            # outputs.loss = mean NLL over non-masked tokens
            nlls.append(outputs.loss.item() * target_len)

        prev_end = end
        if end == T:
            break

    mean_nll = sum(nlls) / T
    ppl = np.exp(mean_nll)
    print(f"Tokens: {T}, Mean NLL: {mean_nll:.4f} nats, PPL: {ppl:.2f}")
    return ppl

Bits-per-Byte (BPB)

Raw perplexity is tokenizer-dependent: GPT-4 with byte-pair encoding and LLaMA with SentencePiece tokenize the same text into different numbers of tokens, making PPL values incomparable. Bits-per-byte (BPB) normalizes by character count:

BPB = (1/|chars|) Σₜ −log₂ p_model(xₜ|x<t) × |chars_in_token_t|

Equivalently: BPB = log₂(PPL) / avg_chars_per_token. Lower is better; the theoretical minimum is the entropy rate of the true distribution.

import torch
import numpy as np
from transformers import AutoTokenizer, AutoModelForCausalLM
from typing import Tuple

def bits_per_byte(
    text: str,
    model_name: str = "gpt2",
    stride: int = 512
) -> Tuple[float, float, float]:
    """Compute bits-per-byte (BPB) — tokenizer-agnostic perplexity.

    Returns:
        Tuple of (ppl, bpb, avg_chars_per_token)
    """
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(model_name)
    model.eval()

    encodings = tokenizer(text, return_tensors="pt")
    input_ids = encodings.input_ids  # (1, T)
    tokens = tokenizer.convert_ids_to_tokens(input_ids[0].tolist())

    # Character length per token (for BPB computation)
    # Tokens may have special chars (Ġ for GPT-2 word boundaries)
    char_lengths = [len(t.replace('Ġ', ' ').replace('Ċ', '\n')) for t in tokens]
    total_chars = sum(char_lengths)
    avg_chars_per_token = total_chars / len(tokens)

    max_length = model.config.n_positions
    T = input_ids.shape[1]
    total_nll_bits = 0.0

    with torch.no_grad():
        for begin in range(0, T, stride):
            end = min(begin + max_length, T)
            chunk = input_ids[:, begin:end]
            outputs = model(chunk, labels=chunk)
            # Convert from nats to bits
            nll_bits = outputs.loss.item() / np.log(2)
            total_nll_bits += nll_bits * (end - begin)

    mean_nll_bits_per_token = total_nll_bits / T
    ppl = 2 ** mean_nll_bits_per_token
    bpb = mean_nll_bits_per_token / avg_chars_per_token

    print(f"Model: {model_name}")
    print(f"Avg chars/token: {avg_chars_per_token:.3f}")
    print(f"PPL: {ppl:.2f}")
    print(f"BPB: {bpb:.4f} bits/char")
    return ppl, bpb, avg_chars_per_token

Comparing Perplexity Across Tokenizers

import numpy as np
from transformers import AutoTokenizer
from typing import List, Dict

def tokenizer_comparison(
    text: str,
    model_names: List[str]
) -> Dict[str, dict]:
    """Compare tokenization statistics across different model tokenizers.

    This demonstrates why raw PPL is incomparable across tokenizers.
    """
    results = {}
    chars = len(text)

    for model_name in model_names:
        try:
            tokenizer = AutoTokenizer.from_pretrained(model_name)
            tokens = tokenizer.encode(text)
            n_tokens = len(tokens)
            avg_chars = chars / n_tokens

            results[model_name] = {
                "n_tokens": n_tokens,
                "avg_chars_per_token": avg_chars,
                "compression_ratio": chars / n_tokens,
                # Hypothetical: same true entropy in BPB=0.9
                # PPL would differ by tokenizer compression ratio
                "hypothetical_ppl_at_bpb_0.9": 2 ** (0.9 * avg_chars)
            }
            print(f"\n{model_name}:")
            print(f"  Tokens: {n_tokens}, Avg chars/token: {avg_chars:.2f}")
            print(f"  Hypothetical PPL (BPB=0.9): {results[model_name]['hypothetical_ppl_at_bpb_0.9']:.1f}")
        except Exception as e:
            print(f"  {model_name}: error — {e}")

    return results

compression and prediction. Given input X and target Y, we seek a compressed
representation Z that maximizes I(Z;Y) while minimizing I(X;Z)."""

Per-Domain Perplexity Breakdown

A single aggregate PPL number obscures important variation. A model might achieve low PPL on news text (well-represented in training) but high PPL on code or mathematics. Per-domain analysis reveals generalization gaps and informs targeted training data collection.

import numpy as np
from typing import Dict, List

def per_domain_perplexity(
    domain_texts: Dict[str, List[str]],
    log_probs_fn,  # function(text) -> list of per-token log probs
) -> Dict[str, dict]:
    """Compute perplexity broken down by domain.

    Args:
        domain_texts: Dict mapping domain name to list of text samples.
        log_probs_fn: Callable returning per-token log₂ probs for a string.
    Returns:
        Dict with per-domain PPL and BPB statistics.
    """
    results = {}

    for domain, texts in domain_texts.items():
        all_log_probs = []
        all_chars = 0

        for text in texts:
            lp = log_probs_fn(text)  # list of log₂ probs
            all_log_probs.extend(lp)
            all_chars += len(text)

        mean_nll = -np.mean(all_log_probs)   # bits per token
        ppl = 2 ** mean_nll
        avg_cpt = all_chars / len(all_log_probs)
        bpb = mean_nll / avg_cpt

        results[domain] = {"ppl": ppl, "bpb": bpb, "n_tokens": len(all_log_probs)}
        print(f"  {domain:15s}: PPL={ppl:7.1f}, BPB={bpb:.4f}, tokens={len(all_log_probs)}")

    return results

# Typical GPT-4 level model benchmark results (illustrative)
print("Typical domain-level perplexity (GPT-4 class model):")
domains = {
    "Wikipedia": 3.2,
    "News": 5.1,
    "Python code": 2.8,
    "Math proofs": 8.4,
    "Legal text": 6.7,
    "Medical text": 9.2,
}
for domain, ppl in domains.items():
    bpb_approx = np.log2(ppl) / 3.8  # assume 3.8 chars/token
    print(f"  {domain:15s}: PPL={ppl:.1f}, BPB≈{bpb_approx:.3f}")

Perplexity vs Downstream Task Performance

Scenario PPL Trend Downstream Correlation Why?
Same model family, different size Larger → lower PPL Strong positive More capacity → better distribution fit → better tasks
Different tokenizers, same LLM size Tokenizer-dependent Weak (use BPB instead) PPL is tokenizer-dependent; BPB normalizes this
Pre-train PPL vs instruction following Lower pre-train PPL Moderate RLHF/SFT can degrade PPL while improving instruction quality
Domain-specific PPL vs domain tasks In-domain PPL Strong Low code PPL → better code generation
PPL after quantization Slight PPL increase Moderate Quantization artifacts don't always hurt downstream tasks equally
PPL on web text vs safety benchmarks Uncorrelated Near zero Safety is a fine-tuning property, not captured by raw text PPL

PPL Does Not Capture Semantic Quality: A model can achieve low perplexity by assigning high probability to plausible but factually wrong text. PPL measures distributional fit, not factual accuracy, logical coherence, or instruction-following ability. Always pair PPL with downstream task evaluations (MMLU, HumanEval, etc.) for a complete picture.

Compression as an Evaluation Framework

Because perplexity equals 2^{cross-entropy}, a language model is implicitly a compression algorithm: encode each token as −log₂ p_model(xₜ|x<t) bits. Better models compress better. This connection motivates evaluating LLMs by their compression ratio on standardized corpora — a tokenizer-agnostic, compute-cheap alternative to running benchmark suites. The Hutter Prize competition awarded prizes for compressing 100 MB of Wikipedia, directly incentivizing advances in language modeling long before the transformer era.

  • PPL = 2^{H(p,q)} — perplexity is compressed bits per token exponentiated
  • BPB < 1.0 means the model compresses text below 1 bit/char — comparable to gzip on structured data
  • Random baseline PPL = vocabulary size (e.g., 50,000 for GPT-2) — equivalent to uniform guessing
  • State-of-the-art models (GPT-4 class) achieve BPB ≈ 0.7–0.9 on diverse English text
  • Compression ratio on a held-out corpus is directly comparable across model architectures and tokenizers

Perplexity is the workhorse of language model evaluation: information-theoretically grounded, easy to compute, and strongly predictive within a model family. Its limitations — tokenizer dependence, insensitivity to semantic quality, poor cross-domain aggregation — are well understood and addressed by BPB and per-domain breakdowns. A complete evaluation always uses PPL/BPB alongside task-based benchmarks.
