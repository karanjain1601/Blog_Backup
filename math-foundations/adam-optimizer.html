Adam — Adaptive Learning Rates and Bias Correction

First Moment — Momentum Term

Adam maintains an exponential moving average of past gradients (first moment): m_t = β₁ m_{t-1} + (1-β₁) g_t. With the default β₁=0.9, this is a smoothed version of the gradient that reduces oscillation just like momentum. The first moment acts as the numerator of the update step — it tracks the direction the optimizer wants to move. Unlike SGD momentum, Adam normalizes by the square root of the second moment, making the effective step size nearly constant regardless of gradient scale.

import numpy as np
import matplotlib.pyplot as plt

def adam(grad_fn, x0, lr=0.001, beta1=0.9, beta2=0.999, eps=1e-8, n_steps=500):
    x = np.array(x0, dtype=float)
    m = np.zeros_like(x)   # first moment (momentum)
    v = np.zeros_like(x)   # second moment (variance)
    path = [x.copy()]
    losses = []
    for t in range(1, n_steps + 1):
        g = grad_fn(x)
        m = beta1 * m + (1 - beta1) * g       # first moment update
        v = beta2 * v + (1 - beta2) * g**2    # second moment update
        m_hat = m / (1 - beta1**t)            # bias-corrected first moment
        v_hat = v / (1 - beta2**t)            # bias-corrected second moment
        x = x - lr * m_hat / (np.sqrt(v_hat) + eps)  # parameter update
        path.append(x.copy())
        losses.append(0.5 * float(np.dot(x, x)))  # toy loss
    return np.array(path), losses

# Ill-conditioned quadratic
grad_fn = lambda x: np.array([x[0], 50*x[1]])
path_adam, losses_adam = adam(grad_fn, x0=[3.0, 2.0], lr=0.05)

plt.figure(figsize=(8, 3))
plt.semilogy(losses_adam)
plt.xlabel('Step'); plt.ylabel('Loss')
plt.title('Adam Convergence on Ill-Conditioned Quadratic')

Second Moment — Gradient Variance

The second moment v_t = β₂ v_{t-1} + (1-β₂) g_t² estimates the uncentered variance of the gradient. Large v_t for a parameter means that parameter receives large, variable gradients — so the adaptive step size η / √v_hat becomes small. Small v_t means small or sparse gradients, so the effective step is large. This adaptive scaling makes Adam particularly effective for sparse gradients (e.g., NLP embeddings where most tokens appear infrequently).

Bias Correction

Both m_t and v_t are initialized to zero, creating a bias toward zero in early steps. Without correction, early updates are far smaller than they should be. The bias correction factors (1-β₁^t) and (1-β₂^t) compensate: m̂_t = m_t / (1-β₁^t) and v̂_t = v_t / (1-β₂^t). At t=1 with β₁=0.9: the correction factor is 1/(1-0.9) = 10×, inflating the first moment to its true scale. By t=50, the factor is close to 1 and bias correction becomes negligible.

Why Bias Correction Matters: Without bias correction, Adam's first update has m_hat = 0.1*g1 instead of g1, giving a 10x too-small step. This causes a 'warm-up' period where Adam barely moves. With bias correction, the first update is already at full strength. Omitting bias correction is a common source of bugs in custom Adam implementations — the optimizer still converges but trains much slower in early steps.

import numpy as np
import matplotlib.pyplot as plt

np.random.seed(42)
# Simulate gradient stream: constant gradient g=1 with noise
T = 100
g_stream = 1.0 + 0.2 * np.random.randn(T)
beta1, beta2, eps = 0.9, 0.999, 1e-8

m_raw, v_raw = 0.0, 0.0      # without bias correction
m_bc, v_bc = 0.0, 0.0        # with bias correction
steps_raw, steps_bc = [], []

for t in range(1, T + 1):
    g = g_stream[t-1]
    # Update raw (no bias correction)
    m_raw = beta1 * m_raw + (1 - beta1) * g
    v_raw = beta2 * v_raw + (1 - beta2) * g**2
    steps_raw.append(m_raw / (np.sqrt(v_raw) + eps))
    # Update with bias correction
    m_bc = beta1 * m_bc + (1 - beta1) * g
    v_bc = beta2 * v_bc + (1 - beta2) * g**2
    m_hat = m_bc / (1 - beta1**t)
    v_hat = v_bc / (1 - beta2**t)
    steps_bc.append(m_hat / (np.sqrt(v_hat) + eps))

plt.figure(figsize=(9, 3))
plt.plot(steps_raw, label='Without bias correction (underestimates early)')
plt.plot(steps_bc, label='With bias correction (correct scale from step 1)')
plt.axhline(1.0, color='k', linestyle='--', alpha=0.5, label='True gradient = 1.0')
plt.xlabel('Step t'); plt.ylabel('Effective step magnitude')
plt.title('Adam Bias Correction: Effect on Early Steps')
plt.legend(); plt.grid(True, alpha=0.3); plt.tight_layout()
plt.savefig('adam_bias_correction.png', dpi=150)
plt.show()

Effective Step Size

The effective step size for parameter i at step t is η_t,i = η ⋅ m̂{t,i} / (√v̂ + ε). When the gradient has been consistently large and positive, m̂ and √v̂ grow proportionally, so the ratio stays bounded. The effective step size per parameter is bounded by roughly η (the nominal learning rate) in most regimes. This makes Adam robust to hyperparameter choice: for a wide range of loss landscapes, lr=1e-3 works well without tuning.

Adaptive Rates for Sparse Gradients

For parameters that receive rare gradient updates (e.g., word embeddings in NLP), the second moment v̂ stays small because most g_t² contributions are zero or near-zero. This gives a large effective step size η/√v̂ when the parameter finally gets a non-zero gradient, producing a large corrective update. In contrast, SGD with a fixed learning rate updates all parameters equally per step. Adam's adaptive rates make it naturally suited for sparse optimization problems in NLP and recommendation systems.

import torch
import torch.nn as nn
import torch.optim as optim
import matplotlib.pyplot as plt

torch.manual_seed(42)
# Simulate sparse gradient problem: embedding lookup
vocab_size, embed_dim, seq_len, n_steps = 1000, 64, 10, 300
embedding = nn.Embedding(vocab_size, embed_dim)

def make_sparse_batch():
    # Only 10 out of 1000 tokens appear per batch
    tokens = torch.randint(0, 50, (seq_len,))  # sparse: only first 50 tokens
    return tokens

def run_with_optimizer(opt_class, lr, n_steps=300):
    emb = nn.Embedding(vocab_size, embed_dim)
    opt = opt_class(emb.parameters(), lr=lr)
    losses = []
    for _ in range(n_steps):
        tokens = make_sparse_batch()
        vecs = emb(tokens)
        # Target: embeddings should have unit norm
        loss = ((vecs.norm(dim=1) - 1.0)**2).mean()
        opt.zero_grad(); loss.backward(); opt.step()
        losses.append(loss.item())
    return losses

losses_sgd = run_with_optimizer(lambda p, lr: optim.SGD(p, lr=lr), lr=0.1)
losses_adam = run_with_optimizer(lambda p, lr: optim.Adam(p, lr=lr), lr=0.01)
plt.figure(figsize=(8, 3))
plt.plot(losses_sgd, label='SGD lr=0.1 (uniform updates)')
plt.plot(losses_adam, label='Adam lr=0.01 (adaptive, sparse-friendly)')
plt.xlabel('Step'); plt.ylabel('Loss'); plt.yscale('log')
plt.title('Sparse Embedding Optimization: Adam vs SGD')
plt.legend(); plt.grid(True, alpha=0.3); plt.tight_layout()
plt.savefig('adam_sparse.png', dpi=150); plt.show()

Default Hyperparameters

The Adam paper recommends β₁=0.9, β₂=0.999, ε=1e-8, and lr=1e-3. These defaults work remarkably well across a wide range of tasks without tuning. The ε term prevents division by zero but also sets a floor on step sizes: when v̂ < ε², the step is approximately m̂/ε, which can be large. Increasing ε (e.g., to 1e-6 or 1e-5) reduces step sizes for parameters with small gradients and can improve stability on some tasks.

Adam Non-Convergence and AMSGrad

Reddi et al. (2018) showed that Adam can fail to converge even for simple convex problems. The issue: the exponential moving average v_t can forget informative past gradients too quickly, allowing the effective step to increase at bad times. AMSGrad fixes this by replacing v̂t with the maximum of all past v̂_s: v̂̂_t = max(v̂̂, v̂_t). This guarantees the effective step never increases for a given parameter, ensuring convergence for convex problems at the cost of slightly slower adaptation.

import numpy as np
import matplotlib.pyplot as plt

def amsgrad(grad_fn, x0, lr=0.01, beta1=0.9, beta2=0.99, eps=1e-8, n_steps=2000):
    x = np.array(x0, dtype=float)
    m, v, v_max = np.zeros_like(x), np.zeros_like(x), np.zeros_like(x)
    losses = []
    for t in range(1, n_steps + 1):
        g = grad_fn(t, x)
        m = beta1 * m + (1 - beta1) * g
        v = beta2 * v + (1 - beta2) * g**2
        v_max = np.maximum(v_max, v)   # AMSGrad: take running max of v
        m_hat = m / (1 - beta1**t)
        x = x - lr * m_hat / (np.sqrt(v_max) + eps)
        losses.append(float(x**2))
    return losses

def adam_standard(grad_fn, x0, lr=0.01, beta1=0.9, beta2=0.99, eps=1e-8, n_steps=2000):
    x = np.array(x0, dtype=float)
    m, v = np.zeros_like(x), np.zeros_like(x)
    losses = []
    for t in range(1, n_steps + 1):
        g = grad_fn(t, x)
        m = beta1 * m + (1 - beta1) * g
        v = beta2 * v + (1 - beta2) * g**2
        m_hat = m / (1 - beta1**t); v_hat = v / (1 - beta2**t)
        x = x - lr * m_hat / (np.sqrt(v_hat) + eps)
        losses.append(float(x**2))
    return losses

# Adversarial gradient sequence that causes Adam to diverge (Reddi 2018)
def adversarial_grad(t, x):
    return np.array([10.0 if t % 101 == 1 else -1.0])

losses_adam = adam_standard(adversarial_grad, [0.5])
losses_ams = amsgrad(adversarial_grad, [0.5])
plt.figure(figsize=(9, 3))
plt.plot(losses_adam, alpha=0.8, label='Adam (may not converge)')
plt.plot(losses_ams, alpha=0.8, label='AMSGrad (guaranteed convergent)')
plt.xlabel('Step'); plt.ylabel('x^2 (distance to min)')
plt.title('Adam vs AMSGrad on Adversarial Gradient Sequence')
plt.legend(); plt.grid(True, alpha=0.3); plt.tight_layout()
plt.savefig('amsgrad.png', dpi=150); plt.show()
