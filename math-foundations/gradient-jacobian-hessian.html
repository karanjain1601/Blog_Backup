Gradient, Jacobian, and Hessian

Three differential objects appear constantly in ML theory: the gradient (first-order, scalar output), the Jacobian (first-order, vector output), and the Hessian (second-order, scalar output). Each captures a different aspect of how a function changes locally, and each has distinct computational costs and ML applications.

The Gradient: Direction of Steepest Ascent

For f: Rⁿ → R, the gradient ∇f(x) ∈ Rⁿ has components [∂f/∂x₁, ..., ∂f/∂xₙ]. Geometrically it is the steepest ascent direction at x; algebraically it is the unique vector such that D_u f = ∇f · u for all unit u. Computed in one backward pass by reverse-mode AD, regardless of n.

import torch
from torch.autograd.functional import jacobian

def vector_func(x):
    # f: R^3 -> R^2
    f1 = x[0]**2 + x[1] * x[2]       # grad_f1 = [2x0, x2, x1]
    f2 = torch.sin(x[0]) + x[1]**2    # grad_f2 = [cos(x0), 2x1, 0]
    return torch.stack([f1, f2])

x = torch.tensor([1.0, 2.0, 0.5])

# Full 2x3 Jacobian
J = jacobian(vector_func, x)
print('Input shape:', x.shape, ' Output shape:', vector_func(x).shape)
print('Jacobian shape:', J.shape, '  (m x n: outputs x inputs)')
print('Jacobian:')
print(J.numpy().round(4))

# Manual check: row i = gradient of f_i
J_manual = torch.tensor([
    [2*x[0].item(), x[2].item(), x[1].item()],
    [torch.cos(x[0]).item(), 2*x[1].item(), 0.0]
])
print('Manual Jacobian:')
print(J_manual.numpy().round(4))
print('Max abs discrepancy:', (J - J_manual).abs().max().item())

The Jacobian Matrix

For f: Rⁿ → Rᵐ, the Jacobian J ∈ Rᵐˣⁿ has J_{ij} = ∂fᵢ/∂xⱼ. Row i is the gradient of fᵢ. Computing the full Jacobian costs O(m) backward passes (reverse-mode) or O(n) forward passes (forward-mode). For a loss function (m=1), J reduces to the gradient row vector, computed in one backward pass.

Jacobian Cost Trade-off: Use reverse-mode when m << n (typical in ML: scalar loss, many weights). Use forward-mode when n << m (rare; e.g., sensitivity of many outputs to one scalar input). JAX's jacfwd and jacrev both exist for this reason.

The Hessian Matrix

For f: Rⁿ → R, the Hessian H ∈ Rⁿˣⁿ has H_{ij} = ∂²f/∂xᵢ∂xⱼ. By Clairaut's theorem (continuity of second partials), H is symmetric. The Hessian captures curvature: along eigenvector v with eigenvalue λ, the function curves like λ·v² — large λ means steep curvature, small λ means flat curvature.

import torch
import numpy as np
from torch.autograd.functional import hessian

def saddle_func(x):
    # f(x,y) = x^2 - y^2  (saddle at origin)
    return x[0]**2 - x[1]**2

def bowl_func(x):
    # f(x,y) = x^2 + 2*y^2  (convex bowl, minimum at origin)
    return x[0]**2 + 2*x[1]**2

for name, func in [('Saddle: x^2-y^2', saddle_func), ('Bowl: x^2+2y^2', bowl_func)]:
    x = torch.zeros(2)
    H = hessian(func, x).numpy()
    eigs = np.linalg.eigvalsh(H)

    if all(eigs > 0):
        crit = 'Local minimum (all eigenvalues > 0)'
    elif all(eigs < 0):
        crit = 'Local maximum (all eigenvalues < 0)'
    else:
        crit = 'Saddle point (mixed eigenvalues)'

    kappa = np.max(np.abs(eigs)) / (np.min(np.abs(eigs)) + 1e-10)
    print('')
    print(name)
    print('  Hessian:', H.tolist())
    print('  Eigenvalues:', eigs.round(4).tolist())
    print('  Critical point type:', crit)
    print('  Condition number kappa:', round(kappa, 2))

Hessian Eigenvalues and Curvature

The sign pattern of Hessian eigenvalues determines the type of critical point: all positive → local minimum, all negative → local maximum, mixed signs → saddle point. The ratio λ_max/λ_min (condition number κ) governs gradient descent convergence speed: convergence rate is O((κ-1)/(κ+1)) per iteration — ill-conditioned problems converge exponentially slowly.

Quantity Input → Output Shape Compute Cost Primary Use in ML
Gradient ∇f f:Rⁿ→R n-vector 1 backward pass Parameter updates (GD, Adam)
Jacobian J_f f:Rⁿ→Rᵐ m×n matrix min(m,n) AD passes Sensitivity analysis, NTK
Hessian H_f f:Rⁿ→R n×n matrix n HVPs or n² partials Curvature, Newton step
HVP Hv f:Rⁿ→R, v∈Rⁿ n-vector 2 backward passes Conjugate gradient, KFAC, PCG

Hessian-Vector Products Without Materializing H

Forming the full Hessian costs O(n²) memory — infeasible for large models. But the Hessian-vector product Hv can be computed in O(n) using the identity: Hv = ∇(∇f · v). This requires only two backward passes and never builds H. HVPs power conjugate gradient optimization (Newton-CG), curvature estimation (KFAC), and Hessian-free deep learning.

import torch

def f(x):
    # Scalar function: sum of cubes + sum of neighbor products
    return (x**3).sum() + (x[:-1] * x[1:]).sum()

def hvp(func, x, v):
    # Hessian-vector product Hv without materializing the n x n Hessian.
    # Identity: Hv = nabla(nabla_f . v)
    # Cost: O(n) -- equivalent to two backward passes.
    x = x.detach().requires_grad_(True)
    grad_f = torch.autograd.grad(func(x), x, create_graph=True)[0]
    g_v    = (grad_f * v).sum()              # scalar: nabla_f . v
    hvp_r  = torch.autograd.grad(g_v, x)[0] # nabla(nabla_f . v) = Hv
    return hvp_r

n = 2000
x = torch.randn(n)
v = torch.randn(n); v = v / v.norm()   # unit vector

result = hvp(f, x, v)
print('Input dim n:', n)
print('HVP output shape:', result.shape)
print('HVP norm:', round(result.norm().item(), 4))
print('Memory for full H: %.1f MB' % (n * n * 4 / 1e6))
print('HVP requires: O(n) only -- no matrix stored.')
print('Used in: conjugate gradient, KFAC, influence functions.')

Condition Number and Ill-Conditioning

The condition number κ(H) = λ_max/λ_min measures how much curvature varies across directions. High κ means gradient descent makes tiny progress in the flat directions while potentially overshooting in steep directions. Remedies: preconditioning (Adam approximates diagonal preconditioner via v), gradient clipping, or second-order methods.

import numpy as np

def f(x):
    # f(x,y) = x^3 + 2*x*y^2 + y^4
    return x[0]**3 + 2*x[0]*x[1]**2 + x[1]**4

def analytical_hessian(x):
    # H = [[6x, 4y], [4y, 4x + 12y^2]]
    return np.array([
        [6*x[0],           4*x[1]         ],
        [4*x[1], 4*x[0] + 12*x[1]**2     ]
    ])

def numerical_hessian(func, x, h=1e-4):
    # 4-point central difference for each H_ij
    n = len(x)
    H = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            ei = np.eye(n)[i]; ej = np.eye(n)[j]
            H[i, j] = (func(x+h*ei+h*ej) - func(x+h*ei-h*ej)
                       - func(x-h*ei+h*ej) + func(x-h*ei-h*ej)) / (4*h**2)
    return H

x0 = np.array([1.0, 2.0])
H_a = analytical_hessian(x0)
H_n = numerical_hessian(f, x0)
print('Analytical Hessian:')
print(H_a)
print('Numerical Hessian:')
print(H_n.round(4))
print('Max abs error:', np.abs(H_a - H_n).max())
eig = np.linalg.eigvalsh(H_a)
print('Eigenvalues:', eig.tolist())
print('Condition number kappa:', round(eig.max() / eig.min(), 3))

High Condition Number Kills Gradient Descent: If κ(H) = 1000, gradient descent converges at rate ≈ (999/1001)^k per step — thousands of iterations to halve the error. Adam's adaptive learning rate acts as a diagonal preconditioner that partially compensates for this.

Summary

  • Gradient ∇f ∈ Rⁿ: one backward pass, used for every optimizer update
  • Jacobian J ∈ Rᵐˣⁿ: generalizes gradient to vector outputs; row i = gradient of fᵢ
  • Hessian H ∈ Rⁿˣⁿ: symmetric matrix of second partials; eigenvalues = curvatures
  • HVP Hv: O(n) via double-backward; avoids O(n²) Hessian materialization
  • Condition number κ = λ_max/λ_min: high κ causes slow GD convergence
  • Critical point classification: all λ>0 (min), all λ<0 (max), mixed (saddle)

In practice, modern ML rarely materializes the Hessian. Newton-CG uses HVPs; Adam approximates diagonal curvature via second moments; K-FAC approximates the Fisher information matrix (related to Hessian at a minimum) using Kronecker structure.
