Multi-Object Tracking: SORT, DeepSORT, and HOTA Evaluation

Multi-object tracking (MOT) requires detecting objects in each frame and linking detections across frames into consistent trajectories. The tracking-by-detection paradigm — detect first, then associate — dominates modern MOT. Quality depends on both the detector (for missed detections) and the association algorithm (for ID switches and fragmented tracks over time).

****: MOTA (the old standard MOT metric) weights false negatives and ID switches equally — but an ID switch is far less harmful than a missed detection for most applications. HOTA separates detection accuracy (DetA) from association accuracy (AssA), giving a more informative evaluation.

The standard tracking-by-detection pipeline processes each frame through an object detector (typically YOLO or Faster R-CNN) to produce bounding boxes and confidence scores. These detections are associated with existing tracks using a cost matrix combining spatial overlap (IoU) and optionally appearance similarity from a re-ID model for robustness.

Track management handles three states: active tracks receiving matched detections, tentative tracks for new detections not yet confirmed, and lost tracks awaiting re-association. A track is confirmed after N consecutive matches and deleted after M missed frames. Typical values are N=3 and M=30 at standard video frame rates for pedestrian tracking.

The Kalman filter models each track as a state vector (x, y, w, h, vx, vy, vw, vh) — bounding box center, dimensions, and velocities. It predicts the next state before observing any detection, providing a prior for association. The update step corrects the state with the matched detection, balancing prediction vs. measurement by their respective covariances.

# SORT: Kalman predict then IoU associate
for track in active_tracks:
    track.kalman_filter.predict()
    predicted_bbox = state_to_bbox(track.kf.x)

# Compute IoU cost matrix
cost_matrix = 1 - iou_matrix(predicted_bboxes, detections)
assignments = hungarian(cost_matrix)

for t_idx, d_idx in assignments:
    active_tracks[t_idx].kalman_filter.update(
        bbox_to_obs(detections[d_idx]))

IoU-based association works well when objects move slowly relative to frame rate. The Hungarian algorithm finds the globally optimal assignment minimizing total cost. Unmatched tracks are marked lost; unmatched detections become new tentative tracks. SORT achieves competitive accuracy with simple motion but struggles with occlusion and fast-moving objects.

DeepSORT augments SORT's motion-based association with appearance features from a re-ID network, typically a ResNet or lightweight MobileNet trained on person re-ID datasets. The appearance feature vector is computed for each detection crop and compared to a gallery of features stored per track, enabling re-association after long occlusions in video.

# DeepSORT: appearance + motion cost fusion
reid_feat = reid_model(det_crop)  # shape: (1, 128)

# Cosine distance to stored track features
cost_app = 1 - cosine_sim(reid_feat, track_feats)
cost_mot = mahalanobis(predicted_bbox, det_bbox)
cost = cost_app + lambda_val * cost_mot
assign = hungarian(cost)

# Update appearance memory with moving average
track.feats = 0.9 * track.feats + 0.1 * reid_feat

# ByteTrack: two-stage matching strategy
high_dets, low_dets = split_by_confidence(
    detections, thresh=0.5)

# Stage 1: match all tracks to high-conf detections
assign1 = hungarian(iou_cost(tracks, high_dets))
unmatched_tracks = get_unmatched(tracks, assign1)

# Stage 2: match remaining tracks to low-conf dets
assign2 = hungarian(iou_cost(
    unmatched_tracks, low_dets))
# Prevents ID switch on occluded/distant objects

ByteTrack's two-stage matching is a key innovation: it first matches high-confidence detections to all tracks, then attempts to recover tracks using low-confidence detections that might correspond to occluded or distant objects. This significantly reduces ID switches and track fragmentation compared to simply discarding low-confidence detections outright.

MOTA (Multiple Object Tracking Accuracy) was the primary MOT metric for years but conflates detection and association errors in a way that obscures their relative contributions. HOTA (Higher Order Tracking Accuracy) decomposes performance into DetA (detection accuracy) and AssA (association accuracy), offering cleaner diagnostic information for tracker development.

IDF1 measures the ratio of correctly identified detections to the mean of ground truth and computed detections. It is sensitive to identity consistency over long tracks. MOTA penalizes false positives, false negatives, and ID switches additively — making it straightforward to game by tuning detection thresholds toward high recall at the expense of precision.

# HOTA metric decomposition
TP = true_positive_detections
FP = false_positive_detections
FN = false_negative_detections

# Detection accuracy component
DetA = TP / (TP + FP + FN)

# Association accuracy (averaged over IoU thresholds)
# TPA/FPA/FNA: matched/extra/missed trajectory pairs
AssA = mean_over_alpha(TPA / (TPA + FPA + FNA))

HOTA = math.sqrt(DetA * AssA)
print(f'HOTA: {HOTA:.3f}')

HOTA is computed at multiple IoU thresholds (alpha from 0.05 to 0.95) and averaged, similar to COCO mAP. This makes it robust to bounding box localization quality. The geometric mean of DetA and AssA ensures neither metric dominates — a tracker cannot achieve high HOTA by sacrificing association quality for detection accuracy or vice versa.

Modern MOT trackers are evaluated on MOT17 and MOT20 benchmarks, which provide sequences in diverse settings. HOTA has become the preferred primary metric because it balances detection and association quality equally. ByteTrack-style two-stage matching is now standard practice, significantly outperforming single-stage IoU matching in crowded and occluded sequences.

Re-ID appearance features are critical for handling long occlusions and crowded scenes but add latency and require domain-specific training to generalize across different cameras. For real-time applications, motion-only trackers like SORT remain competitive when combined with high-quality detectors and appropriately tuned Kalman filter noise covariance parameters.
