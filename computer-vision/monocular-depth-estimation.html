Monocular Depth Estimation: Self-Supervised and Learned Approaches

Overview

Monocular depth estimation infers per-pixel distance from a single RGB image. Unlike stereo or LiDAR, no explicit geometry sensor is needed, making it attractive for autonomous driving, robotics, and AR/VR. Modern approaches fall into two camps: self-supervised methods that exploit video consistency losses, and supervised methods trained on LiDAR or stereo data.

Deep learning treats depth as a dense pixel-wise regression problem. Early CNNs (Eigen et al., 2014) used multi-scale encoder-decoder networks. Vision Transformers later showed that global self-attention captures long-range depth cues — flat roads, overhanging branches, and distant buildings benefit from global context that local convolutions systematically miss.

Scale Ambiguity Problem

Without a reference scale, a monocular camera cannot distinguish a small nearby object from a large distant one — both project identically onto the image plane. Methods predicting relative depth (disparity or normalised inverse depth) sidestep this ambiguity but produce outputs that cannot feed motion planners or 3D reconstruction pipelines needing metric distance.

****: Monocular depth is inherently scale-ambiguous — a small nearby object and a large distant one project identically. Self-supervised methods resolve this via camera pose estimation; metric methods use sparse LiDAR or stereo supervision to fix the scale.

Metric depth methods fix scale via explicit supervision: sparse LiDAR projections in KITTI, or pseudo-GT from multi-view stereo reconstruction. ZoeDepth and Depth Anything V2 learn both relative geometry and a metric head conditioned on camera intrinsics, achieving sub-metre accuracy on indoor benchmarks while generalising to outdoor driving scenes with competitive AbsRel.

Self-Supervised Depth via View Synthesis

Self-supervised depth learning repurposes image reconstruction as a proxy training task. A depth network and a pose network jointly predict per-pixel depth D and relative camera pose T. The target frame is warped into the source view using D and T via differentiable bilinear sampling; photometric consistency between warped and source images supervises both networks without any depth labels.

# Self-supervised photometric loss for monocular depth
warped = grid_sample(target_frame, flow_from_depth_and_pose)
photometric = F.l1_loss(warped, source_frame)
ssim_loss = 1 - ssim(warped, source_frame)
reprojection = 0.85 * ssim_loss + 0.15 * photometric
# Edge-aware smoothness regularisation
edge_aware_smooth = smooth_loss(depth, source_frame)
total_loss = reprojection + 0.001 * edge_aware_smooth

The edge-aware smoothness term penalises depth discontinuities not aligned with image edges, preventing over-smoothing in textureless regions like roads and sky. The Monodepth2 auto-mask discards pixels where photometric loss is lower before warping — removing the training signal from static background and moving objects that violate the rigid-scene assumption.

DPT and Transformer Depth

Dense Prediction Transformer (DPT) uses a Vision Transformer backbone to extract patch-level features at multiple network depths. Unlike CNNs, ViT produces spatially consistent feature tokens at every layer. DPT reassembles tokens from layers 3, 6, 9, and 12 into 2D feature maps, fuses them with progressive upsampling blocks, and decodes to a full-resolution depth output.

# DPT (Dense Prediction Transformer) depth head
features = vit_backbone(image)          # ViT patch tokens
hooks = [features[3], features[6],
         features[9], features[12]]
# Reassemble + fusion blocks upsample to full res
depth = dpt_head(hooks)                 # fused multi-scale
depth = F.relu(depth)                  # non-negative depth

DPT-Hybrid replaces full ViT with ResNet50 for early layers, cutting FLOPs while retaining long-range attention. MiDaS v3 uses DPT-Hybrid trained on 10+ mixed datasets with scale-and-shift-invariant loss, producing robust relative depth predictions. Fine-tuning this relative encoder on metric supervision (KITTI, NYUv2) then converts outputs to absolute depth efficiently.

Metric vs Relative Depth

Relative depth models output disparity or normalised inverse depth, invariant to global scale and shift. These generalise across camera types but cannot support motion planning. Metric depth models output depth in metres and require metric supervision — sparse LiDAR, or the learned scale anchoring used by ZoeDepth, which attaches a small metric head per dataset domain to the encoder.

# Affine alignment of relative depth to sparse metric GT
def align_depth(pred, sparse_gt):
    mask = sparse_gt > 0
    p, g = pred[mask], sparse_gt[mask]
    scale, shift = np.polyfit(p, g, 1)
    aligned = pred * scale + shift
    ratio = np.maximum(aligned[mask]/g, g/aligned[mask])
    delta1 = (ratio < 1.25).mean()
    abs_rel = np.abs(aligned[mask] - g).mean() / g.mean()
    return aligned, abs_rel, delta1

Key Takeaways

Self-supervised methods like Monodepth2 match supervised performance on KITTI without depth labels by learning from temporal video consistency. Their weakness is scale ambiguity and poor generalisation to scenes with slow camera motion or moving objects dominating the frame — the photometric loss breaks where Lambertian appearance assumptions do not hold.

DPT-based methods set the quality bar for relative depth estimation. Training on large, diverse datasets with scale-and-shift-invariant loss gives strong zero-shot transfer, making MiDaS v3 and Depth Anything excellent off-the-shelf depth priors for tasks including 3D inpainting, video editing, and NeRF initialisation from sparse input views.

Metric depth is an active frontier. ZoeDepth, Depth Pro (Apple), and UniDepth show that combining large relative-depth encoders with a metric head trained on diverse data achieves generalised metric depth without dense LiDAR. The open challenge is indoor-outdoor domain shift: depth value distributions differ by two to three orders of magnitude across scene types.
