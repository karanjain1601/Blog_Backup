LiDAR 3D Object Detection: BEV Representations and Voxel Networks

LiDAR 3D Object Detection: BEV Representations and Voxel Networks

Overview

LiDAR (Light Detection and Ranging) sensors emit laser pulses and measure return times to produce precise 3D point clouds of the environment. In autonomous driving, LiDAR 3D object detection localizes vehicles, pedestrians, and cyclists with centimeter-level precision, far exceeding camera-only methods in depth accuracy.

A typical automotive LiDAR (e.g., Velodyne HDL-64E) produces ~130 000 points per frame at 10 Hz. Each point carries (x, y, z, intensity). The sparse, unordered nature of point clouds makes applying standard 2D CNNs non-trivial. Two main paradigms emerged: range-image projection and Bird's Eye View (BEV) feature maps.

BEV representations project the 3D point cloud onto the ground plane. This view preserves metric scale, avoids the perspective foreshortening of camera images, and aligns naturally with HD map lanes. BEV-based detectors like PointPillars and CenterPoint dominate autonomous driving leaderboards due to their speed-accuracy balance.

Point Cloud to BEV

BEV projection discretizes the X-Y plane into a grid with resolution r (typically 0.05–0.2 m/pixel). For each grid cell, features are aggregated from all points falling within it. Common features include maximum height, mean intensity, point density, and height percentiles across a configurable number of height channels.

import numpy as np\n\nH, W, C = 800, 800, 5\nres = 0.1  # meters per pixel\nbev_map = np.zeros((H, W, C), dtype=np.float32)\n\nfor pt in points:\n    bx = int((pt[0] - x_min) / res)\n    by = int((pt[1] - y_min) / res)\n    if 0 <= bx < H and 0 <= by < W:\n        # Max height, mean intensity, count\n        bev_map[bx, by, 0] = max(bev_map[bx, by, 0], pt[2])\n        bev_map[bx, by, 1] += pt[3]  # intensity\n        bev_map[bx, by, 2] += 1      # density

BEV maps are rotation-equivariant in the horizontal plane, which simplifies anchor design — a vehicle always appears as a rectangle of fixed width and length regardless of sensor tilt. The main limitation is information loss along the Z axis: stacked objects (e.g., a cyclist under a bridge) may be conflated in a single-height BEV channel.

Voxelization and Sparse Convolution

Voxelization divides 3D space into a uniform grid of voxels. Unlike BEV, voxels retain the Z dimension, enabling full 3D reasoning. The key challenge is that only ~0.01% of voxels are occupied, making dense 3D CNNs memory-prohibitive. Sparse convolution (spconv) computes activations only at occupied voxels, reducing memory by 100x.

import numpy as np\n\nvoxel_size = np.array([0.05, 0.05, 0.1])  # x, y, z in meters\nmin_bound = np.array([-50., -50., -5.])\n\n# Assign each point to a voxel\nindices = ((points[:, :3] - min_bound) / voxel_size).astype(int)\n\n# Get unique occupied voxels\nunique_voxels, inverse = np.unique(indices, axis=0, return_inverse=True)\n\n# Group points by voxel (max N_max per voxel)\nfor vid in range(len(unique_voxels)):\n    voxel_pts = points[inverse == vid][:32]

Within each voxel, a small PointNet-style MLP aggregates the variable number of points into a fixed-dimensional feature. VoxelNet (Zhou & Tuzel, 2018) pioneered this approach with Voxel Feature Encoding (VFE) layers. SECOND (2018) replaced dense 3D convolutions with sparse convolutions, achieving real-time performance.

PointPillars Architecture

PointPillars (Lang et al., 2019) achieves the best speed-accuracy tradeoff by treating each vertical column (pillar) of points as a pseudo-image channel. Points within a pillar are encoded with a simplified PointNet. The pillar features are then scattered back to their BEV locations, forming a pseudo-image for a standard 2D backbone.

# PointPillars forward pass (conceptual)\npillar_size = [0.16, 0.16]  # x, y in meters\nmax_points_per_pillar = 100\n\n# Step 1: Pillarize — assign points to pillar grid\npillar_feat, pillar_coords = pillarize(\n    points, pillar_size, max_points_per_pillar\n)\n\n# Step 2: PointNet per pillar → (N_pillars, C=64)\npillar_feat = pillar_pointnet(pillar_feat)\n\n# Step 3: Scatter to pseudo-image (H x W x C)\npseudo_img = scatter(pillar_feat, pillar_coords, canvas_size=(H, W))\n\n# Step 4: 2D backbone + detection head\ndetections = detection_head(backbone_2d(pseudo_img))

By avoiding 3D convolutions entirely, PointPillars runs at 62 Hz on a single GPU while achieving 77.3% mAP on KITTI Car (moderate). The scatter operation is differentiable and efficiently implemented with index_put_ on GPU. The two-stage variant (PointPillars + second-stage refinement) further improves accuracy with minimal latency cost.

Anchor-Free BEV Detection

tip: PointPillars' key insight: compress the z-dimension (height) into learned features per pillar, then treat the result as a pseudo-image for fast 2D convolutions. This avoids expensive 3D convolutions while retaining height information in the pillar features.

Anchor-based detectors require careful anchor design (size, aspect ratio, number per location) and suffer from class imbalance between foreground anchors and background. CenterPoint replaces anchors with a heatmap-based detection head inspired by CenterNet, predicting a Gaussian heatmap peak at each object center in BEV.

# CenterPoint anchor-free decoding\nimport torch\nimport torch.nn.functional as F\n\n# Render Gaussian heatmap targets\nheatmap = gaussian_render(centers_bev, sigma=2)\n\n# Decode: apply NMS on heatmap peaks\nheatmap_nms = F.max_pool2d(heatmap, kernel_size=3, padding=1, stride=1)\npeaks = (heatmap == heatmap_nms) & (heatmap > score_thresh)\n\n# Regression heads for size, height, rotation, velocity\noffset = offset_head(bev_feat)\nsize = size_head(bev_feat)\nvel = velocity_head(bev_feat)

CenterPoint's two-stage version refines each detected center with a 2D RoI grid pooling head, extracting local BEV features and predicting refined box parameters. This second stage adds ~3ms and improves NDS by ~2 points. For multi-class detection, a separate heatmap channel is predicted per class to avoid inter-class suppression.

Key Takeaways

Choose PointPillars when latency is paramount (edge compute, embedded GPU). Use CenterPoint or TransFusion when accuracy matters more. For camera-LiDAR fusion, TransFusion's cross-attention mechanism between image tokens and LiDAR BEV features consistently outperforms late-fusion approaches on nuScenes by 3–5 NDS points.

Data augmentation is critical for LiDAR 3D detection: ground-truth database sampling (copy-paste random objects into training scenes), global rotation/flipping, and random scaling dramatically improve small-object detection (pedestrians, cyclists). Mixup at the point cloud level also helps with occlusion robustness.

Evaluation uses 3D IoU thresholds (0.7 for cars, 0.5 for pedestrians, 0.5 for cyclists on KITTI). nuScenes uses a composite NDS metric combining mAP with velocity, attribute, and orientation errors. Always report per-class AP separately — aggregate metrics can hide poor performance on safety-critical categories like pedestrians.

Temporal aggregation of multiple LiDAR sweeps (e.g., 5 consecutive frames) significantly improves detection of sparse objects like distant pedestrians. CenterPoint with 10 sweeps improves pedestrian AP by ~8 points on nuScenes. Compensate for ego-motion between sweeps using odometry before concatenating point clouds.
