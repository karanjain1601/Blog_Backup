INT8 Quantization for Vision Models: PTQ and QAT

INT8 quantization maps 32-bit floating-point weights and activations to 8-bit integers, reducing memory footprint by 4× and enabling hardware-accelerated integer arithmetic on CPUs, GPUs, and mobile NPUs. For vision models, INT8 inference typically runs 2–4× faster than FP32 with less than 1% Top-1 accuracy loss.

Two main approaches exist: Post-Training Quantization converts a trained FP32 model to INT8 with a short calibration step, while Quantization-Aware Training simulates quantisation during training. PTQ is faster to apply; QAT recovers more accuracy for aggressive compression ratios below 8 bits or on small datasets.

Symmetric quantization maps the range [-max, max] to [-127, 127] with zero_point=0, simplifying multiply-accumulate hardware. Asymmetric quantization maps [x_min, x_max] to [0, 255] with an integer zero-point, which better accommodates one-sided distributions such as ReLU output activations that are always non-negative.

scale = (x_max - x_min) / 255\nzero_point = round(-x_min / scale)\nx_int8 = clamp(round(x / scale + zero_point), 0, 255)\nx_dequant = scale * (x_int8 - zero_point)

The scale factor bridges float and integer domains: a large scale means coarse quantization with significant rounding error; a small scale reduces rounding error but may clip outliers. Calibration with a representative dataset — 100 to 1000 images — determines optimal scale and zero-point values for each tensor.

PTQ converts a pre-trained FP32 model to INT8 in three steps: configure the quantization scheme, run calibration to collect activation statistics, and convert the model to use integer arithmetic. No retraining is required, making PTQ the fastest path to a quantized model suitable for initial latency benchmarking.

model.eval()\nmodel.qconfig = get_default_qconfig('x86')\nprepare(model, inplace=True)\ncalibrate(model, calib_loader)\nconvert(model, inplace=True)

Calibration collects activation statistics across a representative dataset — typically 100 to 1000 images. Min-max calibration is simple but sensitive to outliers; percentile clipping at the 99.9th percentile and entropy-based KL calibration yield better accuracy on models with heavy-tailed activation distributions.

info: Activations are harder to quantize than weights — they vary per input, making a fixed scale suboptimal. Per-channel quantization for weights (different scale per output channel) with dynamic calibration for activations gives the best INT8 accuracy with minimal effort.

QAT inserts fake-quantize nodes into the computational graph that round values to the nearest representable integer during the forward pass and use a straight-through estimator for gradients. This allows the model's weight distributions to adapt to the quantization grid across full training epochs, closing the PTQ accuracy gap.

model.train()\nmodel.qconfig = get_default_qat_qconfig('x86')\nprepare_qat(model, inplace=True)\nfor epoch in range(qat_epochs):\n    train_epoch(model, loader, optimizer)\nconvert(model, inplace=True)

QAT typically requires 10–20% of the original training schedule with a reduced learning rate (10× lower) and converges faster when initialised from the PTQ model. Freeze batch normalisation statistics after the first few epochs to prevent activation drift during fake-quantize updates and stabilise the training curve.

Per-channel quantization assigns a separate scale to each output channel of a weight tensor, dramatically reducing rounding error on layers with high inter-channel weight variance. This is critical for depthwise-separable convolutions in MobileNets, where channel weight ranges vary by up to 10× across individual filters.

for layer in model.layers:\n    quantize_layer(model, layer)\n    acc = evaluate(model, val_loader)\n    sensitivity[layer.name] = baseline_acc - acc\n    restore_fp32(model, layer)\n\nsensitive = sorted(sensitivity, key=lambda k: -sensitivity[k])[:top_k]\nkeep_fp16(model, sensitive)

Mixed-precision quantization keeps accuracy-sensitive layers in FP16 or FP32 while quantizing the remaining 80–90% of parameters to INT8. Sensitivity analysis — measuring accuracy drop when each layer is quantized in isolation — identifies which layers to protect, typically the first convolution and the final classifier head.

PTQ is the right first step: apply calibrated INT8 with per-channel weight quantization and test latency on the target device. If the accuracy drop exceeds 1%, switch to QAT with 10–20% of original training epochs. Avoid INT4 without QAT — quantization error compounds across layers and typically exceeds 3% Top-1 loss.

Profile both theoretical FLOPs and actual device latency. INT8 gives 2–3× speedup on x86 CPUs via VNNI instructions and 3–4× on ARM via NEON int8 kernels. For Transformer-based vision models such as ViT and Swin Transformer, attention softmax and LayerNorm operations are quantization-sensitive and should remain in FP16.
