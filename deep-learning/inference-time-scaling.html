Inference-Time Scaling Laws

Overview

Inference-time scaling laws describe how model accuracy improves as additional computation is invested during inference rather than training. The central empirical finding — established across mathematics, coding, and logical reasoning benchmarks — is that accuracy increases predictably, often log-linearly, with the amount of inference compute deployed. This scaling operates through three distinct mechanisms: (1) generating longer output sequences so the model can perform more reasoning steps before producing a final answer; (2) sampling multiple independent solutions and selecting among them using a scoring function or majority vote; and (3) conducting structured search over partial solutions, guided by a learned reward model that scores intermediate reasoning steps. These mechanisms are not mutually exclusive — state-of-the-art systems such as o1, o3, and DeepSeek-R1 combine all three, generating long chain-of-thought traces, sampling many candidates, and using verifiers to select final answers. The o1/o3 series demonstrated that the inference compute axis follows scaling laws qualitatively similar to those governing training compute, enabling principled prediction of achievable accuracy at a given inference budget.

The Test-Time Compute Paradigm

The traditional scaling paradigm for language models focused exclusively on training compute: larger models trained on more data with more GPU-hours achieve lower perplexity and higher benchmark scores. Test-time compute scaling offers a complementary axis — for a fixed trained model, how much accuracy can be recovered by spending more compute at inference time? The answer depends heavily on the task structure. For problems with verifiable correct answers — competition mathematics, formal theorem proving, code with executable test suites — test-time scaling is highly effective because an external verifier can distinguish correct from incorrect outputs without human judgment. For open-ended tasks such as creative writing or summarisation, the absence of a ground-truth verifier limits the utility of sampling multiple outputs. The o1 series demonstrated that for hard reasoning tasks, a small model with a large inference budget can match or exceed a much larger model with a standard inference budget, fundamentally changing the economics of deploying capable AI systems. This paradigm shift has practical consequences: accuracy is now a tunable dial that operators can adjust at serving time by controlling token budgets, sample counts, and search parameters, independently of the underlying trained model.

  • Token budget scaling: generating more reasoning tokens per response before the final answer
  • Sample count scaling: generating N independent solutions and selecting the best via a reward model
  • Guided search: using a process reward model to score and prune partial solutions at each step
  • Self-consistency: majority voting over sampled answers without a separate reward model
  • Verifier-in-loop: iteratively generating and checking solutions until one passes all checks

Scaling with More Tokens

The simplest form of inference-time scaling is to allow the model to generate more tokens before producing a final answer. On mathematical reasoning benchmarks such as MATH and GSM8K, accuracy increases substantially as the maximum token budget grows from 64 to 4096 tokens, with diminishing returns beyond that threshold. The relationship is approximately log-linear: each doubling of the token budget produces a roughly constant absolute improvement in accuracy, but the magnitude of those improvements shrinks as the budget grows large. This diminishing-returns behaviour reflects the structure of hard problems: the easiest gains come from giving the model space to write out intermediate steps it would otherwise skip, while the hardest problems require qualitatively different reasoning strategies that more tokens alone cannot provide. Models trained with reinforcement learning to use thinking tokens — such as DeepSeek-R1 and o1 — achieve substantially better accuracy-per-token efficiency than base models with simple chain-of-thought prompting, because RL training teaches the model to allocate reasoning effort productively across different token budget levels rather than padding output with redundant text. Empirically, RL-trained thinking models achieve the same accuracy as base models at roughly 4–8× fewer tokens, reducing the marginal cost of inference-time scaling.

import anthropic
import matplotlib.pyplot as plt
from typing import List, Dict

client = anthropic.Anthropic()

def token_budget_sweep(problems: List[Dict], model: str = "claude-opus-4-5") -> None:
    # Sweep max_tokens budgets and measure accuracy vs tokens generated.
    budgets = [64, 256, 1024, 4096, 8192]
    accs, avg_toks = [], []
    for budget in budgets:
        correct, total_tok = 0, 0
        for prob in problems:
            msg = client.messages.create(
                model=model, max_tokens=budget,
                messages=[{"role": "user", "content": prob["question"]}],
            )
            total_tok += msg.usage.output_tokens
            if prob["answer"].strip() in msg.content[0].text:
                correct += 1
        acc = correct / len(problems)
        accs.append(acc); avg_toks.append(total_tok / len(problems))
        print(f"budget={budget:5d}  avg_tokens={total_tok/len(problems):7.1f}  acc={acc:.3f}")
    plt.plot(avg_toks, accs, "o-"); plt.xlabel("Avg Tokens Generated")
    plt.ylabel("Accuracy"); plt.title("Accuracy vs Token Budget"); plt.grid(True); plt.show()

Scaling with More Samples

Sampling multiple independent solutions from the same model and selecting the best is the most widely studied form of test-time scaling. The best-of-N strategy generates N solutions using temperature sampling (typically T=0.8–1.0) and returns the candidate with the highest score according to an outcome reward model. The accuracy of best-of-N scales as a power law with N: doubling N typically yields a constant fraction of the remaining error gap to perfect accuracy. This power-law scaling is approximated by acc(N) = 1 − (1 − p)^N where p is the per-sample success probability, though this formula underestimates accuracy when samples are correlated through shared failure modes. Self-consistency — selecting the answer that appears most frequently across N samples — achieves 70–80% of the gain of ORM-based selection with zero reward model cost, making it the preferred approach when accuracy matters more than compute cost and no labelled data is available to train a reward model. The key hyperparameter is sampling temperature: too low produces correlated samples with little diversity, while too high produces incoherent solutions. The optimal temperature for best-of-N on MATH is approximately 0.7–0.9, and should be tuned per model and task domain. On AIME 2024, o1-mini with N=64 samples approaches o1 accuracy at roughly 4× lower per-sample cost.

import anthropic
import numpy as np
from collections import Counter
from typing import List, Dict

client = anthropic.Anthropic()

def sample_and_vote(problem: Dict, sample_ns: List[int] = [1, 4, 8, 16, 32, 64]) -> None:
    # Generate up to max(sample_ns) samples, then evaluate majority vote at each N.
    cached: List[str] = []
    for n in sample_ns:
        while len(cached) < n:
            r = client.messages.create(
                model="claude-haiku-4-5", max_tokens=512, temperature=0.8,
                messages=[{"role": "user", "content": problem["question"]}],
            )
            cached.append(r.content[0].text.strip())
        subset = cached[:n]
        vote = Counter(subset).most_common(1)[0][0]
        correct = (vote == problem["answer"])
        pass_at_n = np.mean([a == problem["answer"] for a in subset])
        print(f"N={n:3d}  majority_vote_correct={correct}  pass@N={pass_at_n:.2f}")

Search and Verification

Structured search over reasoning paths combines token budget scaling with sample count scaling by guiding generation toward high-quality partial solutions rather than completing each sample independently. Beam search with a process reward model (PRM) maintains a set of B active reasoning paths (the beam), expands each by generating K candidate next steps, scores all B×K candidates with the PRM, and retains the top B for the next step. This algorithm explores the space of solutions more efficiently than random sampling because it focuses compute on the most promising partial solutions early, avoiding wasting tokens on paths the PRM predicts will fail. The quality of search guidance depends critically on PRM calibration: a well-calibrated PRM assigns high scores to steps that lead to correct final answers and low scores to steps that lead to incorrect ones. Monte Carlo Tree Search (MCTS) extends beam search with backpropagation of outcome signals, enabling the search algorithm to revise step scores based on downstream outcomes, but at the cost of higher engineering complexity and inference overhead. In practice, simple beam search with a well-trained PRM achieves 80–90% of MCTS accuracy at a fraction of the implementation complexity, and is the recommended starting point for production systems. Combining beam search with outcome verification — where each completed beam is checked by an executable verifier — further pushes accuracy toward ceiling on tasks with objective correctness criteria such as code generation and formal proofs.

import anthropic
import re
from typing import List, Dict

client = anthropic.Anthropic()

def score_step(step: str, context: str) -> float:
    # Approximate PRM: ask the model to rate the reasoning step.
    prompt = "Rate this reasoning step 0.0 to 1.0. Context: " + context[:300] + " Step: " + step
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=8,
                               messages=[{"role": "user", "content": prompt + " Score:"}])
    m = re.search(r"[01]\.\d+", r.content[0].text)
    return float(m.group()) if m else 0.5

def prm_beam_search(problem: str, beam_w: int = 3, n_steps: int = 5) -> str:
    beams: List[Dict] = [{"steps": [], "score": 1.0}]
    for _ in range(n_steps):
        cands: List[Dict] = []
        for beam in beams:
            ctx = problem + " | " + " | ".join(beam["steps"])
            for _ in range(beam_w):
                r = client.messages.create(model="claude-haiku-4-5", max_tokens=150,
                                           messages=[{"role": "user", "content": ctx + " Next step:"}])
                step = r.content[0].text.strip()
                cands.append({"steps": beam["steps"] + [step], "score": score_step(step, ctx)})
        beams = sorted(cands, key=lambda b: b["score"], reverse=True)[:beam_w]
        print(f"step_done  best_score={beams[0]['score']:.3f}")
    return " | ".join(beams[0]["steps"])

Inference vs Training Compute Tradeoffs

A key question for practitioners is whether to invest compute budget in training a larger model or in deploying a smaller model with a higher inference compute budget. The answer depends on task structure, deployment volume, and acceptable latency. For high-volume, latency-sensitive serving such as autocomplete or interactive chat, training a larger model amortises the training cost over many inference calls, each of which must be fast. For low-volume, high-stakes problems such as medical diagnosis assistance, competitive mathematics, or legal reasoning, allocating significant inference compute to a smaller model can achieve better accuracy per dollar. The cross-over point — where a smaller model with N-sample inference matches a larger model with single-sample inference — is empirically around N=16–64 for models two to four times different in parameter count on MATH-level reasoning tasks. Beyond this range, test-time compute cannot fully compensate for parameter scale on tasks that require broad world knowledge distributed across many parameters. A critical practical consideration: inference compute scales with N per query, but training compute is a one-time fixed cost. For a problem solved one million times per day, even a modest per-inference overhead accumulates rapidly, and the break-even point between investing in training vs. inference shifts substantially toward training for high-volume deployments. Organisations should profile the accuracy-compute Pareto frontier for their specific workload before committing to an architecture choice.

import anthropic
import math
import matplotlib.pyplot as plt
from dataclasses import dataclass
from typing import List
@dataclass
class Config:
    label: str; params_b: float; tokens: int; samples: int; accuracy: float
def flops(c: Config) -> float:
    return 2.0 * c.params_b * 1e9 * c.tokens * c.samples
configs: List[Config] = [
    Config("70B x 1",    70, 512,  1,  0.72),
    Config("8B x 4",      8, 512,  4,  0.68),
    Config("8B x 16",     8, 512,  16, 0.74),
    Config("8B x 64",     8, 1024, 64, 0.79),
    Config("8B+PRM x4",   8, 2048, 4,  0.77),
    Config("8B+PRM x16",  8, 2048, 16, 0.81),
]
xs = [math.log10(flops(c)) for c in configs]
ys = [c.accuracy for c in configs]
plt.figure(figsize=(9, 5)); plt.scatter(xs, ys, s=90)
for c, x, y in zip(configs, xs, ys):
    plt.annotate(c.label, (x, y), xytext=(5, 3), textcoords="offset points")
plt.xlabel("log10(FLOPs)"); plt.ylabel("Accuracy on MATH")
plt.title("Pareto Frontier: Parameter Scale vs Test-Time Compute"); plt.grid(True); plt.show()

Practical Implications

The inference-time scaling findings have several concrete implications for AI system design and deployment. First, accuracy on hard reasoning tasks is no longer a fixed property of a trained model — it can be controlled at serving time by adjusting the inference compute budget, enabling operators to trade latency and cost against quality on a per-request basis. Second, the existence of a smooth accuracy-compute Pareto frontier means that operators can choose the operating point that best matches their cost and latency constraints, rather than committing to a single fixed model size. Third, training models to use inference compute well — via RL on thinking tokens or via distillation from larger thinking models — is now a first-class training objective, because a model that efficiently distributes its reasoning across a given token budget achieves far better performance than one that simply generates more tokens without structured self-improvement. Fourth, evaluating model quality with single-sample greedy decoding systematically underestimates the achievable performance of models that support extended reasoning, making best-of-N evaluation with appropriate sample counts a necessary complement to standard benchmarking. Fifth, retrieval-augmented generation (RAG) and tool use compose naturally with test-time scaling: models that can call tools or search databases within their reasoning trace effectively have access to external compute, extending the scaling curve further. Organisations deploying capable reasoning models should profile all three scaling axes for their task domain and design serving infrastructure that can flexibly adjust compute allocation based on query difficulty.

Key Empirical Finding: The o1/o3 findings show that inference-time compute scales predictably with accuracy — for hard reasoning tasks, a small model with many thinking tokens can match a large model at less total compute. On AIME 2024, o1 with a 32K token thinking budget matched GPT-4o performance at roughly 8x lower parameter count, demonstrating that the accuracy-compute curve for inference compute can intersect the training-compute Pareto frontier at practically relevant operating points for competition mathematics.

  1. Profile the accuracy-compute curve for your specific task class before committing to a scaling strategy
  2. Use majority vote (self-consistency) for medium-difficulty tasks before investing in reward model training
  3. Train a lightweight outcome reward model on domain-specific data for best-of-N selection in high-stakes settings
  4. Set token budgets dynamically based on detected problem difficulty rather than a fixed maximum
  5. Monitor for diminishing returns: for most tasks, N > 64 samples or tokens > 8192 shows minimal marginal gains

Key Takeaways

  • Inference-time compute scales predictably with accuracy via three mechanisms: longer outputs, more samples, and guided search
  • Best-of-N with an outcome reward model is the most effective and easiest-to-implement test-time scaling strategy
  • Self-consistency (majority vote) captures 70-80% of reward-model gain at zero additional model cost
  • The accuracy-compute Pareto frontier favours test-time scaling for low-volume, high-stakes tasks and training-compute scaling for high-volume, latency-sensitive deployments
  • Models trained with RLVR on thinking tokens use inference compute far more efficiently than base models with naive chain-of-thought prompting
  • Evaluating capable reasoning models with single-sample greedy decoding systematically underestimates their true performance ceiling — always complement with best-of-N benchmarking
