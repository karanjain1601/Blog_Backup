Evaluating Quantized Models: Perplexity and Beyond

Evaluating a quantized large language model requires more than a single number. Perplexity on a standard corpus gives a fast, reproducible signal, but it does not capture the full picture: a model that maintains low perplexity can still degrade sharply on structured reasoning, mathematical problem-solving, or commonsense inference tasks that require precise token predictions at key positions. A rigorous quantization evaluation pipeline combines corpus-level perplexity on WikiText-2 and C4 with zero-shot task accuracy across multiple benchmarks, uses statistical thresholds to detect catastrophic quantization failures, and runs as a CI gate before any quantized checkpoint is deployed to production.

Overview

The standard quantization evaluation workflow operates at three levels of granularity. First, perplexity on a held-out text corpus provides a token-level quality signal that is sensitive to the average quality of next-token predictions across the distribution. Second, zero-shot benchmark accuracy on tasks such as ARC-Easy, HellaSwag, WinoGrande, and MMLU measures the model's ability to complete structured reasoning tasks that are important for real-world use. Third, a regression suite enforces hard thresholds on both perplexity delta and per-task accuracy drop, ensuring that any quantization configuration that degrades model quality beyond acceptable limits is automatically flagged before deployment. Together these three levels form a complete evaluation pipeline that is both fast enough to run on every quantization candidate and sensitive enough to catch subtle quality regressions that perplexity alone would miss.

Perplexity as a Proxy Metric

Perplexity (PPL) measures how well a language model predicts a held-out text corpus. For a sequence of N tokens x_1, ..., x_N, perplexity is defined as exp(-1/N * sum_i log P(x_i | x_1,...,x_{i-1})). A lower perplexity means the model assigns higher average probability to the observed tokens. For quantization evaluation, the key quantity is the perplexity delta: how much does PPL increase when moving from the FP16 reference to the quantized model? A delta below 0.1 points is generally considered negligible; a delta of 0.1-0.5 is acceptable for 4-bit quantization; a delta above 1.0 points is a clear quality regression; and a delta above 5.0 points indicates catastrophic degradation where the model has lost coherence.

Perplexity is attractive because it is fast to compute, dataset-independent (any unlabelled text corpus suffices), and provides a continuous quality signal rather than a binary pass/fail. However, it has well-documented limitations as a proxy for downstream task accuracy. Perplexity is dominated by the most frequent token patterns in the corpus, so a model can maintain low perplexity by accurately predicting common syntactic structures while silently losing the rare, precise predictions needed for mathematical reasoning or factual recall. Several papers have documented cases where a quantized model's perplexity increase was below 0.1 on WikiText-2 but accuracy on MMLU dropped by more than 5 percentage points — a gap large enough to matter in production. This motivates including at least one downstream benchmark alongside perplexity in any quantization evaluation suite.

Wikitext-2 and C4 Benchmarks

WikiText-2 is the standard perplexity benchmark for LLM quantization research. It consists of Wikipedia articles with minimal preprocessing, providing approximately 2M training tokens and 246K test tokens. Its vocabulary is broad, its sentences are well-formed, and its domain — encyclopedic prose — is well-represented in most LLM pretraining datasets, making it a reliable diagnostic for weight rounding errors. C4 (Colossal Cleaned Crawled Corpus) is a larger, more diverse alternative drawn from Common Crawl that better covers the web-text distribution most modern LLMs are trained on. For quantization research, WikiText-2 is preferred because its fixed test set enables reproducible comparison across papers; for deployment validation, C4 is preferable because it better reflects the distribution of real user queries. Evaluating on both and reporting both PPL values is the most complete approach. The standard stride for sliding-window perplexity evaluation is 512 tokens with a context window of 1024 tokens, which balances computational cost against accuracy of the perplexity estimate.

import math
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
from datasets import load_dataset

def compute_ppl(model, tokenizer, text, stride=512, max_len=1024):
    enc = tokenizer(text, return_tensors="pt")
    seq_len, nlls, prev_end = enc.input_ids.size(1), [], 0
    for begin in range(0, seq_len, stride):
        end = min(begin + max_len, seq_len)
        trg_len = end - prev_end
        ids = enc.input_ids[:, begin:end].cuda()
        target = ids.clone()
        target[:, :-trg_len] = -100
        with torch.no_grad():
            nlls.append(model(ids, labels=target).loss * trg_len)
        prev_end = end
        if end == seq_len:
            break
    return math.exp(torch.stack(nlls).sum() / prev_end)

test_text = " ".join(load_dataset("wikitext", "wikitext-2-raw-v1", split="test")["text"])
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
fp16 = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf", torch_dtype=torch.float16).cuda()
fp16_ppl = compute_ppl(fp16, tok, test_text)
del fp16; torch.cuda.empty_cache()
nf4_cfg = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16)
nf4 = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf", quantization_config=nf4_cfg, device_map="auto")
nf4_ppl = compute_ppl(nf4, tok, test_text)
print(f"FP16 PPL: {fp16_ppl:.3f}  |  4-bit NF4 PPL: {nf4_ppl:.3f}  |  Delta: {nf4_ppl - fp16_ppl:+.3f}")

Task-Level Evaluation

The lm-evaluation-harness library (by EleutherAI) provides a unified interface for running zero-shot and few-shot evaluations on hundreds of benchmarks. The most informative tasks for quantization evaluation are: ARC-Easy and ARC-Challenge (multiple-choice science questions requiring factual recall and reasoning), HellaSwag (commonsense NLI requiring understanding of plausible story continuations), WinoGrande (Winograd schema pronoun disambiguation), and MMLU (Massive Multitask Language Understanding — 57 subjects spanning STEM, humanities, and social sciences). Running all four on a 7B model takes 15-45 minutes on a single A100 GPU at limit=250 examples per task, making it feasible as a CI evaluation. The key output is the per-task accuracy drop relative to the FP16 baseline. A relative accuracy drop above 2% on any task warrants investigation; a drop above 5% warrants rejecting the quantization configuration and revisiting calibration or bit-width settings.

import torch
from lm_eval import evaluator
from lm_eval.models.huggingface import HFLM
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

MODEL = "meta-llama/Llama-2-7b-hf"
TASKS = ["arc_easy", "hellaswag", "winogrande", "mmlu"]

def run_eval(model_kwargs, label):
    lm = HFLM(pretrained=MODEL, **model_kwargs)
    res = evaluator.simple_evaluate(model=lm, tasks=TASKS, num_fewshot=0, limit=250, batch_size=8)
    scores = {}
    print(f"\n=== {label} ===")
    for t in TASKS:
        acc = res["results"][t].get("acc,none", res["results"][t].get("acc", 0))
        scores[t] = round(acc * 100, 2)
        print(f"  {t:<14}: {scores[t]:.2f}%")
    return scores

fp16 = run_eval({"dtype": "float16"}, "FP16 Baseline")
nf4_cfg = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16)
nf4 = run_eval({"quantization_config": nf4_cfg}, "4-bit NF4")
print("\nAccuracy drop (NF4 vs FP16):")
for t in TASKS:
    delta = nf4[t] - fp16[t]
    status = "WARN" if delta < -3.0 else "OK"
    print(f"  [{status}] {t:<14}: {delta:+.2f}%")
  • ARC-Easy (acc): Elementary-level science questions; moderately sensitive to quantization — 4-bit NF4 typically drops 0.5-1.5% vs FP16.
  • HellaSwag (acc_norm): Commonsense NLI graded by length-normalized log-likelihood; stable under quantization for 4-bit but degrades at 2-bit.
  • WinoGrande (acc): Pronoun disambiguation requiring world knowledge; requires correct token ordering — small PPL changes can flip answers.
  • MMLU (acc): 57-subject multiple choice exam; the most sensitive to quantization among standard benchmarks due to rare-fact precision requirements.
  • TruthfulQA (mc1/mc2): Measures hallucination; not always included but can reveal quantization-induced confabulation increases.
  • GSM8K (exact_match, 5-shot): Grade-school math; highly sensitive to quantization because it requires correct multi-step numerical reasoning.

Zero-shot Accuracy Degradation

Accuracy degradation under quantization follows predictable patterns across model sizes and quantization methods. For weight-only quantization (GPTQ, AWQ, NF4), 4-bit models typically lose less than 1-2% absolute accuracy on ARC-Easy and HellaSwag but can lose 3-8% on MMLU, particularly in the science and mathematics subcategories where precise numerical token predictions are required. Activation quantization (W8A8) is more aggressive: 8-bit activations introduce quantization error on every token's hidden state, and models above 13B parameters show measurably higher degradation on MMLU than smaller models because larger models have more severe activation outliers that expand the quantization range. The degradation pattern also depends heavily on the task format: multiple-choice tasks are less sensitive to quantization than generative tasks such as code completion or math word problems, because multiple-choice requires only selecting the most probable option from a small set rather than generating a precise sequence.

Catastrophic Quantization

Catastrophic quantization occurs when a quantization configuration pushes a model past a tipping point where perplexity and downstream accuracy collapse non-linearly. This is most common when the bit-width is too low for the model size (e.g., 2-bit quantization on a 7B model without Hessian-based calibration), when the group size is too large for the bit-width (e.g., group_size=1024 with 3-bit weights on a 7B model), or when sensitive layers — particularly the first embedding layer or the last language model head — are quantized as aggressively as intermediate feed-forward layers. Catastrophic quantization is characterized by a PPL spike that is disproportionately larger than the linear trend: while reducing from 8-bit to 4-bit might increase PPL by 0.1 points, reducing from 4-bit to 2-bit with the same group size might increase PPL by 8-15 points. Detecting this non-linearity by fitting a linear trend over bit-width and flagging deviations above a threshold is the key diagnostic technique.

Perplexity Can Be Misleading: Perplexity on wikitext-2 is a fast proxy but can be misleading: models that maintain low PPL sometimes show >5% accuracy drops on reasoning tasks like MMLU — always include at least one downstream benchmark in your evaluation suite. The gap between PPL improvement and task accuracy is especially large for MMLU subcategories involving mathematics, formal science, and factual recall, where precise rare-token predictions matter but contribute minimally to average cross-entropy loss.

import numpy as np
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from datasets import load_dataset

def sweep_and_detect(model_id, bit_cfgs, test_enc, threshold=2.0):
    """Sweep bit configs, fit linear PPL trend, flag deviations as catastrophic."""
    results = []
    for bits, bnb_cfg in bit_cfgs:
        m = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=bnb_cfg, device_map="auto")
        with torch.no_grad():
            ids = test_enc["input_ids"].to(m.device)
            ppl = float(np.exp(m(ids, labels=ids).loss.item()))
        results.append((bits, ppl))
        del m; torch.cuda.empty_cache()
    trend = np.polyfit([b for b, _ in results], [p for _, p in results], 1)
    print(f"{'Bits':>5}  {'PPL':>8}  {'Trend':>8}  {'Delta':>8}  Status")
    for bits, ppl in sorted(results):
        expected = float(np.polyval(trend, bits))
        delta = ppl - expected
        flag = "CATASTROPHIC" if delta > threshold else "OK"
        print(f"{bits:>5}  {ppl:>8.3f}  {expected:>8.3f}  {delta:>+8.3f}  {flag}")
    return results

MODEL = "meta-llama/Llama-2-7b-hf"
tok = AutoTokenizer.from_pretrained(MODEL)
test_text = " ".join(load_dataset("wikitext", "wikitext-2-raw-v1", split="test")["text"][:100])
enc = tok(test_text[:2048], return_tensors="pt")
configs = [
    (8, BitsAndBytesConfig(load_in_8bit=True)),
    (4, BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16)),
    (4, BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="fp4", bnb_4bit_compute_dtype=torch.float16)),
]
sweep_and_detect(MODEL, configs, enc)

Evaluation Pipeline

A production quantization evaluation pipeline combines all three evaluation levels — perplexity, task accuracy, and catastrophic detection — into a single CI-compatible script. The pipeline loads a quantized model checkpoint, runs sliding-window perplexity on a fixed WikiText-2 test slice, runs lm-eval-harness on a reduced task suite (arc_easy, hellaswag, mmlu with limit=250 for speed), compares all outputs against a per-model threshold dictionary, and exits with a non-zero return code if any threshold is violated. The threshold dictionary is model-specific because a 7B model and a 70B model have different baseline perplexities and different sensitivity profiles — a 70B model at 4-bit typically shows smaller relative accuracy drops than a 7B model at the same bit-width, because larger models are more robust to weight perturbations when they have redundant capacity. Thresholds should be calibrated by running the pipeline on the FP16 baseline and a known-good quantization (4-bit GPTQ with group_size=128 is a reliable anchor) and using those as the acceptable quality envelope. The pipeline should store per-run results in a JSON artifact so that trends across quantization configurations can be tracked over time.

The regression suite below defines thresholds inline for clarity. In practice, thresholds are loaded from a per-model YAML config file so that they can be updated without modifying pipeline code. The suite uses sys.exit(1) on failure so that CI systems (GitHub Actions, Jenkins, Buildkite) detect the failure automatically. The pipeline is designed to run in under 30 minutes for a 7B model on a single A100 GPU: perplexity computation on WikiText-2 with stride=512 takes approximately 5 minutes, and the reduced lm-eval suite takes approximately 20 minutes.

import sys
import json
import torch
from pathlib import Path
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

THRESHOLDS = {
    "max_ppl_delta": 0.30,
    "arc_easy": 68.0,
    "hellaswag": 74.0,
    "mmlu": 41.0,
}

def ci_check(fp16_ppl: float, quant_ppl: float, scores: dict, out_path: str = None) -> bool:
    """Assert all quantization quality thresholds pass; sys.exit(1) on failure."""
    fails = []
    delta = quant_ppl - fp16_ppl
    if delta > THRESHOLDS["max_ppl_delta"]:
        fails.append(f"PPL delta {delta:+.3f} exceeds max allowed {THRESHOLDS['max_ppl_delta']}")
    for task in ["arc_easy", "hellaswag", "mmlu"]:
        acc = scores.get(task, 0.0)
        if acc < THRESHOLDS[task]:
            fails.append(f"{task} accuracy {acc:.2f}% below minimum {THRESHOLDS[task]}%")
    report = {"ppl_delta": delta, "scores": scores, "failures": fails, "passed": len(fails) == 0}
    if out_path:
        Path(out_path).write_text(json.dumps(report, indent=2))
    if fails:
        for msg in fails:
            print(f"  [FAIL] {msg}")
        sys.exit(1)
    print(f"  [PASS] delta={delta:+.3f}  arc_easy={scores.get('arc_easy',0):.1f}%  "
          f"hellaswag={scores.get('hellaswag',0):.1f}%  mmlu={scores.get('mmlu',0):.1f}%")
    return True

ci_check(
    fp16_ppl=5.682,
    quant_ppl=5.791,
    scores={"arc_easy": 71.2, "hellaswag": 76.4, "mmlu": 43.8},
    out_path="quant_eval_report.json",
)

Key Takeaways

  • Perplexity on WikiText-2 is the standard fast proxy for quantization quality — always compute with stride=512 and a fixed max context length for reproducibility.
  • The perplexity delta threshold of 0.3 points is a good starting point for 4-bit weight-only quantization on 7B models; tighten to 0.1 for 13B+ models.
  • MMLU is the most sensitive downstream benchmark for detecting quantization quality loss — include it even when evaluating on a subset of 250 examples per subject.
  • 4-bit AWQ and GPTQ with group_size=128 are the highest-quality 4-bit quantization methods on WikiText-2 and most downstream benchmarks.
  • 2-bit quantization (AQLM, QuIP#) produces significant PPL spikes on 7B models — acceptable only on 70B+ models where redundant capacity absorbs the error.
  • Catastrophic quantization is detectable by fitting a linear PPL trend over bit-widths and flagging configs where observed PPL exceeds the trend by more than 2 points.
  • Build a regression suite with per-model threshold dictionaries and run it as a CI gate — use sys.exit(1) on failure so that CI systems catch quantization regressions automatically.
  • Evaluate on both WikiText-2 (for reproducibility) and C4 (for deployment realism) — models can have very different relative rankings on the two corpora depending on pretraining data mix.
  • Never rely on perplexity alone: include at least arc_easy and hellaswag in every quantization evaluation run to catch silent downstream accuracy regressions.
