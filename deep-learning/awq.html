AWQ: Activation-Aware Weight Quantization

AWQ (Activation-aware Weight Quantization) is a post-training quantization algorithm introduced by Lin et al. in 2023 that achieves state-of-the-art accuracy at INT4 without the expensive second-order Hessian computation required by GPTQ. The central observation of AWQ is that weights are not equally important: roughly 1% of weight channels are 'salient'—they correspond to input channels with large activation magnitudes and disproportionately influence model outputs. Uniformly rounding all weights to the nearest 4-bit value treats salient and non-salient channels identically, degrading the critical 1% as much as the rest. AWQ avoids this by computing per-channel scaling factors before quantization: salient channels are scaled up (making their quantization grid finer) while the complementary scaling is applied to the preceding layer's output, keeping the overall computation equivalent. The net effect is that salient weights suffer far less rounding error, preserving model quality without requiring per-weight optimization or Hessian inversion.

Overview

AWQ's design philosophy is elegantly simple: find a diagonal scaling matrix S such that quantizing (W × S^{-1}) in INT4 preserves accuracy better than quantizing W directly, then absorb S^{-1} into the preceding layer's output (or equivalently, multiply the input by S before it reaches this layer). Because the scaling and its inverse cancel algebraically, the model's outputs are unchanged in full precision—the scaling is 'mathematically transparent.' In the quantized model, however, the scaled weight W' = W × S^{-1} has smaller variance in the salient channels (because S^{-1} shrinks their range), giving the INT4 grid more resolution where it matters most. The optimal S is found by grid search on the calibration data: AWQ evaluates a set of candidate scale magnitudes and selects the one that minimizes the reconstruction error of the quantized layer output. This grid search is far cheaper than GPTQ's Cholesky factorization, making AWQ quantization 2–5× faster on large models.

  • Identify salient channels: those with the highest mean activation magnitude across calibration data
  • Compute per-channel scale s: proportional to the activation magnitude, with a tunable exponent alpha
  • Apply weight scaling: W' = W × diag(s)^{-1}, equivalently scale the input by diag(s)
  • Quantize W' to INT4 using standard symmetric or asymmetric quantization
  • Absorb the input scaling into the previous layer (e.g., multiply LayerNorm weights by s)
  • No Hessian computation or error propagation: fast and memory-efficient quantization

Identifying Salient Weights

The salience of a weight channel in AWQ is defined by the activation magnitude of the corresponding input feature, not by the weight value itself. This is a subtle but important distinction: a weight with a large absolute value might still be unimportant if the corresponding input activation is small (the product w × x remains small). Conversely, a weight with a small absolute value but a consistently large activation magnitude is highly salient—its quantization error gets amplified by the large activation. AWQ measures salience by computing the mean absolute value of each input channel across the calibration dataset: s_i = mean_over_tokens(|x_i|). Channels with the top 1% of these magnitudes are identified as salient. This salience measurement requires only a single forward pass over the calibration data with lightweight forward hooks—no backward pass, no Hessian, no matrix inversion.

import torch, torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer
from datasets import load_dataset

def get_channel_magnitudes(model, tokenizer, n=32):
    """Collect per-input-channel activation magnitudes via forward hooks."""
    mags, hooks = {}, []
    def hook_fn(name):
        def fn(mod, inp, out):
            x = inp[0].detach().float().abs().mean(dim=(0, 1))
            mags[name] = x if name not in mags else mags[name]*0.9 + x*0.1
        return fn
    for nm, mod in model.named_modules():
        if isinstance(mod, nn.Linear):
            hooks.append(mod.register_forward_hook(hook_fn(nm)))
    ds = load_dataset("wikitext", "wikitext-2-raw-v1", split="train")
    texts = [ds[i]["text"] for i in range(n*4) if ds[i]["text"].strip()][:n]
    model.eval()
    with torch.no_grad():
        for t in texts:
            enc = tokenizer(t, return_tensors="pt", max_length=512, truncation=True)
            model(**enc.to(next(model.parameters()).device))
    [h.remove() for h in hooks]
    return mags

model = AutoModelForCausalLM.from_pretrained("facebook/opt-125m").cuda()
tok = AutoTokenizer.from_pretrained("facebook/opt-125m")
mags = get_channel_magnitudes(model, tok)
layer_name = sorted(mags.keys())[8]
mag = mags[layer_name]
top1pct = torch.quantile(mag, 0.99)
salient = mag >= top1pct
scale_s = torch.where(salient, mag / mag.mean(), torch.ones_like(mag))
print(f"Layer: {layer_name}")
print(f"Salient channels: {salient.sum().item()} / {mag.shape[0]}")
print(f"AWQ scale range: [{scale_s.min():.2f}, {scale_s.max():.2f}]")

The code above collects per-channel magnitudes using exponential moving averages (EMA) across batches, which provides a stable estimate even with noisy calibration data. The EMA coefficient 0.9 weights recent batches slightly less than earlier ones; in practice, the exact coefficient matters little as long as enough calibration samples are used. After identifying salient channels (top 1%), the scale vector s is computed as the ratio of each channel's magnitude to the mean magnitude, clipped to 1.0 for non-salient channels. This scale is then applied as W' = W / s (or equivalently, the input to the layer is multiplied by s before the weight multiply, and s is absorbed into the preceding LayerNorm or linear layer).

Scaling Before Quantization

The mathematical justification for AWQ's scaling approach comes from analyzing quantization error as a function of scale. For a weight w quantized with scale parameter s (the grid spacing), the expected squared quantization error is approximately (s^2)/12 for uniformly distributed values. If we pre-multiply the weight by a factor alpha < 1 (compressing its range), the effective quantization grid becomes alpha times finer, reducing error by alpha^2 / 12 instead of s^2 / 12—a factor of alpha^2 improvement. For a salient channel where alpha corresponds to s_i^{-1} (the inverse of the activation magnitude), the error reduction is largest precisely for the channels that matter most, because those channels have the largest alpha (their weights are compressed the most). The key constraint is that alpha must be absorbed into the previous layer computation—for a LayerNorm → Linear sequence, the LayerNorm output scaling by alpha is equivalent to multiplying the LayerNorm weight gamma by alpha.

In the AutoAWQ implementation, the scale search uses a grid of candidates: alpha is swept over a range such that 2^{-alpha} × s_i is evaluated for alpha in {0, 0.1, 0.2, ..., 1.0}. For each candidate alpha, the layer output error is evaluated on the calibration data, and the alpha minimizing error is selected. This grid search runs in a few seconds per layer (versus minutes for GPTQ's Cholesky computation), making AWQ quantization of a 7B model feasible in 15–30 minutes on a single GPU. Additionally, AutoAWQ optionally applies activation clipping (the apply_clip option), which clips extreme activation values before quantization to prevent outlier activations from dominating the scale estimate—further improving accuracy.

Per-channel vs Per-group

Like GPTQ, AWQ supports group quantization, where each group of consecutive input channels uses its own scale. With AWQ, the per-channel scaling (the s vector computed from activation magnitudes) is applied first, and then standard per-group INT4 quantization is applied within each group. This two-level scaling—one level from AWQ's salience-based scaling, another from group quantization's local scale—provides extremely fine-grained control over quantization error. The default AutoAWQ configuration uses q_group_size=128, which matches the GPTQ convention and enables direct comparison. At group size 128, AWQ typically achieves 0.1–0.2 PPL lower perplexity than GPTQ at the same group size on standard benchmarks, primarily because AWQ's activation-magnitude-based scaling is better calibrated to the actual sensitivity of each channel than GPTQ's uniform per-group approach.

AWQ vs GPTQ

AWQ and GPTQ are complementary approaches to the same problem—finding good INT4 weights—and their accuracy on standard benchmarks is surprisingly close. GPTQ uses second-order information (Hessian) to optimally correct quantization errors, which in theory should give the best possible reconstruction error for each layer. AWQ uses first-order activation statistics (mean magnitudes) to scale weights before quantization, which is a simpler and faster approximation. In practice, AWQ frequently matches or slightly outperforms GPTQ at 4-bit quantization, especially for models in the 7B–13B parameter range. The reason is that GPTQ's Hessian computation is based on the calibration activations, and with only 128 samples, the estimated Hessian can be noisy—particularly for attention layers where activations have complex dependencies. AWQ's simpler statistic (mean absolute magnitude) is more robust to estimation noise with small calibration sets.

Using AutoAWQ

AutoAWQ is the reference implementation of AWQ for Hugging Face-compatible models. Its quantize() method handles salience computation, scale search, weight scaling, INT4 packing, and optionally activation clipping in a single call. The most important configuration options are: w_bit (4 is standard; 2 and 3 are experimental), q_group_size (128 is the default; smaller values improve accuracy but increase metadata overhead), zero_point (True enables asymmetric quantization, recommended), version ('GEMM' for general GPU compatibility; 'GEMV' for batch size 1 inference), and apply_clip (True to enable activation clipping, which improves accuracy by ~0.05–0.1 PPL at a small quantization time cost). The quantized model is saved in AutoAWQ's own safetensors format, compatible with vLLM, lmdeploy, and text-generation-inference.

from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer
from datasets import load_dataset
import os

model_name = "meta-llama/Llama-2-7b-hf"
quant_config = {
    "w_bit": 4,
    "q_group_size": 128,
    "zero_point": True,
    "version": "GEMM",
}
save_path = "./llama-2-7b-awq-4bit"

tokenizer = AutoTokenizer.from_pretrained(model_name, use_fast=True)
model = AutoAWQForCausalLM.from_pretrained(model_name, safetensors=True)

# Build calibration dataset from wikitext-2
dataset = load_dataset("wikitext", "wikitext-2-raw-v1", split="train")
calib_texts = [row["text"] for row in dataset if len(row["text"].strip()) > 50][:128]

# AWQ quantization: searches optimal per-channel scales to protect salient weights
model.quantize(
    tokenizer,
    quant_config=quant_config,
    calib_data=calib_texts,
)

model.save_quantized(save_path)
tokenizer.save_pretrained(save_path)

size_mb = sum(
    os.path.getsize(os.path.join(save_path, f))
    for f in os.listdir(save_path)
    if f.endswith((".safetensors", ".bin"))
) / 1e6
print(f"Saved to: {save_path}")
print(f"Model size: {size_mb:.0f} MB  (FP16: ~13000 MB)")
print(f"Compression: {13000/size_mb:.1f}x")

Tip: AWQ's key insight: only ~1% of weights are 'salient'; scaling these before rounding to INT4 preserves accuracy far better than uniform quantization at negligible extra cost. If your model will be served in batch sizes greater than 1 (throughput-optimized serving), use version='GEMM' for better parallelism. For single-user, low-latency inference (batch size 1), version='GEMV' uses a specialized kernel that is 20–30% faster at decode time.

Deployment with vLLM

vLLM is the dominant high-throughput LLM serving framework as of 2025, and it has first-class support for AWQ-quantized models. AWQ models loaded through vLLM benefit from continuous batching (packing multiple requests into a single forward pass), PagedAttention (efficient KV cache management), and fused AWQ dequantization kernels that minimize the overhead of converting INT4 weights to FP16 at runtime. A vLLM server with an AWQ-quantized 7B model on a single A100-40GB GPU can sustain 500–800 tokens/second for typical chatbot workloads, compared to 200–300 tokens/second for the same model in FP16—a 2–3× throughput improvement. Memory savings from INT4 also allow larger KV caches, which improves batching efficiency: more concurrent requests can be processed before the KV cache fills the GPU.

from vllm import LLM, SamplingParams
import time

# Load AWQ-quantized model via vLLM (requires vllm >= 0.3.0)
llm = LLM(
    model="./llama-2-7b-awq-4bit",
    quantization="awq",
    dtype="float16",
    gpu_memory_utilization=0.85,
    max_model_len=4096,
)

params = SamplingParams(temperature=0.0, max_tokens=200)
prompts = [
    "Explain AWQ quantization in two sentences:",
    "What is the difference between GPTQ and AWQ?",
    "How does per-channel scaling improve INT4 accuracy?",
]

t0 = time.perf_counter()
outputs = llm.generate(prompts, params)
elapsed = time.perf_counter() - t0

total_tokens = sum(len(o.outputs[0].token_ids) for o in outputs)
print(f"Generated {total_tokens} tokens in {elapsed:.2f}s")
print(f"Throughput: {total_tokens / elapsed:.1f} tokens/s")
for i, out in enumerate(outputs):
    print(f"[{i+1}] {out.outputs[0].text[:100]}")

import torch, time
from transformers import AutoTokenizer, AutoModelForCausalLM
from auto_gptq import AutoGPTQForCausalLM
from awq import AutoAWQForCausalLM
from lm_eval import simple_evaluate

configs = {
    "fp16":     ("meta-llama/Llama-2-7b-hf",    "fp16"),
    "bnb-int8": ("meta-llama/Llama-2-7b-hf",    "bnb8"),
    "gptq-4b":  ("./llama-2-7b-gptq-4bit-g128", "gptq"),
    "awq-4b":   ("./llama-2-7b-awq-4bit",       "awq"),
}
prompt = "The transformer architecture was introduced in the paper"

for name, (path, mode) in configs.items():
    if mode == "gptq":
        m = AutoGPTQForCausalLM.from_quantized(path, device="cuda:0")
    elif mode == "awq":
        m = AutoAWQForCausalLM.from_quantized(path, device="cuda:0")
    elif mode == "bnb8":
        m = AutoModelForCausalLM.from_pretrained(path, load_in_8bit=True, device_map="auto")
    else:
        m = AutoModelForCausalLM.from_pretrained(path, torch_dtype=torch.float16, device_map="cuda:0")
    tok = AutoTokenizer.from_pretrained(path)
    inp = tok(prompt, return_tensors="pt").to("cuda")
    t0 = time.perf_counter()
    with torch.no_grad():
        out = m.generate(**inp, max_new_tokens=100, do_sample=False)
    elapsed = time.perf_counter() - t0
    n_tok = out.shape[1] - inp["input_ids"].shape[1]
    mem_gb = torch.cuda.memory_allocated() / 1e9
    print(f"{name:12s}  {n_tok/elapsed:6.1f} tok/s  {mem_gb:.1f} GB")

Key Takeaways

  • AWQ identifies salient channels by activation magnitude, not weight magnitude
  • Pre-scaling weights before INT4 rounding gives finer grid resolution where it matters most
  • Scaling is mathematically transparent: model outputs are identical in full precision
  • AWQ is 2–5x faster to quantize than GPTQ and achieves comparable or better accuracy
  • Default config: w_bit=4, q_group_size=128, zero_point=True, version=GEMM
  • AWQ + vLLM is the standard production stack for INT4 LLM serving in 2025
  • Only 128 calibration samples are needed; larger sets provide diminishing returns
  • At 7B scale: AWQ achieves ~5.60 PPL vs FP16's 5.47, a difference imperceptible in practice
