Extended Chain-of-Thought and 'Thinking' Models

Overview

Extended chain-of-thought (extended CoT) refers to training language models to generate long internal reasoning traces — sometimes spanning thousands of tokens — before producing a concise final answer. This paradigm, pioneered in the o1 series from OpenAI and independently replicated in DeepSeek-R1 and QwQ-32B, produces models that substantially outperform standard chain-of-thought prompting on competition-level mathematics, formal reasoning, and scientific problem-solving. The central idea is that models given space to reason extensively — exploring multiple approaches, identifying errors in intermediate steps, and revising their own reasoning — achieve accuracy that is qualitatively unreachable with short reasoning traces. Extended CoT models are trained using reinforcement learning with verifiable rewards (RLVR), where the RL signal comes entirely from whether the final answer is correct, with no human annotation of individual reasoning steps. This makes training data collection scalable: any domain with an automatic correctness verifier — mathematics (symbolic verification), code (unit tests), logic puzzles (SAT solvers), formal proofs (proof checkers) — can supply training signal for extended CoT training without human labelling cost.

Standard vs Extended CoT

Standard chain-of-thought prompting (Wei et al., 2022) encourages models to show intermediate steps before a final answer, typically adding 50–200 tokens of reasoning. Extended CoT training pushes this to 1,000–32,000 reasoning tokens by training the model to treat the pre-answer scratchpad as a working memory where it can explore, backtrack, and self-correct. The qualitative difference is significant: standard CoT produces a single linear reasoning path, while extended CoT produces what researchers describe as a metacognitive reasoning process — the model actively monitors its own progress, identifies when an approach is failing, and switches strategies. This self-correction behaviour emerges from RL training: the reward signal propagates credit for correct final answers back through the entire reasoning trace, incentivising the model to develop error-detection and recovery as a learned skill. On AIME 2024 problems (competition mathematics at the level of the top 2.5% of high school students), models with extended CoT achieve 50–70% accuracy while models with standard CoT prompting achieve 5–20%, a qualitative capability gap that cannot be bridged by scaling training data or model size alone under the standard CoT regime.

Training for Extended Thinking

Training a model to generate useful extended reasoning traces requires more than simply allowing long outputs. The model must learn to allocate thinking tokens productively: exploring alternative approaches, identifying errors in previous steps, and synthesising a final answer from a complex scratchpad. This skill is not present in base pretrained models — they produce verbose but unstructured output when given large token budgets without targeted training. The standard training pipeline for extended thinking models begins with supervised fine-tuning on a small dataset of (problem, long-reasoning-trace, answer) triples, where the reasoning traces are either human-written or generated by a much larger model. This SFT phase teaches the model the format and structure of extended reasoning. The SFT model is then fine-tuned with reinforcement learning, using the correctness of the final answer as the reward signal. Because RL training provides signal only on correct vs. incorrect final answers, the model must learn to use its reasoning tokens to improve the probability of correct answers — it cannot learn to produce plausible-looking but incorrect reasoning as a shortcut. This property makes RLVR training substantially more reliable than RLHF on open-ended tasks, where reward hacking is a persistent problem.

import anthropic
from dataclasses import dataclass
from typing import List

client = anthropic.Anthropic()

@dataclass
class ThinkingTrace:
    thinking: str
    answer: str
    thinking_tokens: int
    answer_tokens: int

def generate_extended_cot(problem: str, budget: int = 10000) -> ThinkingTrace:
    # Request extended thinking from a Claude model that supports it.
    resp = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=budget + 2000,
        thinking={"type": "enabled", "budget_tokens": budget},
        messages=[{"role": "user", "content": problem}],
    )
    thinking = next((b.thinking for b in resp.content if b.type == "thinking"), "")
    answer = next((b.text for b in resp.content if b.type == "text"), "")
    think_tok = len(thinking.split())
    ans_tok = resp.usage.output_tokens - think_tok
    print(f"Thinking tokens: ~{think_tok}  Answer tokens: {ans_tok}")
    return ThinkingTrace(thinking, answer, think_tok, ans_tok)

RLVR: RL with Verifiable Rewards

Reinforcement learning with verifiable rewards (RLVR) is the training paradigm that enabled extended CoT models to achieve state-of-the-art accuracy on competition mathematics. The RLVR pipeline generates multiple reasoning traces for each problem from the current policy, evaluates the final answer using a symbolic verifier (for mathematics, this checks exact numerical or algebraic equivalence), assigns a binary reward (+1 correct, -1 or 0 incorrect), and updates the policy to increase the probability of reasoning traces that led to correct answers. The key algorithmic choice is how to update the policy given the sparse binary reward signal. GRPO (Group Relative Policy Optimisation), used in DeepSeek-R1, estimates the baseline by averaging rewards within a group of K completions for the same problem, avoiding the need for a separate critic model. PPO (Proximal Policy Optimisation), as used in o1, uses a learned value function as baseline, which provides lower-variance gradient estimates at the cost of additional memory and compute for the critic. Both approaches empirically converge to models with strong extended reasoning capabilities, suggesting that the quality of the verifiable reward signal matters more than the specific RL algorithm. One critical finding from DeepSeek-R1 is that RLVR training causes emergent self-reflection — the model spontaneously learns to insert phrases like 'wait, let me reconsider' and 'I made an error on step 3' as trained behaviours that improve final answer accuracy, even though these phrases were never explicitly supervised.

import torch
from transformers import AutoTokenizer, AutoModelForCausalLM
from typing import List

def verify(generated: str, gold: str) -> float:
    return 1.0 if gold.strip() in generated else -1.0

def rlvr_step(
    model: AutoModelForCausalLM,
    tokenizer: AutoTokenizer,
    prompts: List[str],
    golds: List[str],
    k: int = 4,
) -> float:
    opt = torch.optim.AdamW(model.parameters(), lr=1e-6)
    total = 0.0
    for prompt, gold in zip(prompts, golds):
        ids = tokenizer(prompt, return_tensors="pt")
        outs = [model.generate(**ids, max_new_tokens=512, do_sample=True, temperature=0.8)
                for _ in range(k)]
        texts = [tokenizer.decode(o[0], skip_special_tokens=True) for o in outs]
        rewards = [verify(t, gold) for t in texts]
        baseline = sum(rewards) / k
        for out, r in zip(outs, rewards):
            loss = -(r - baseline) * model(**ids, labels=out).loss
            loss.backward(); total += loss.item()
    opt.step(); opt.zero_grad()
    return total / len(prompts)

Thinking Token Budgets

Extended CoT models can operate across a wide range of thinking token budgets, and their accuracy scales predictably with budget. On AIME 2024, accuracy increases from roughly 30% at 1K thinking tokens to 70–80% at 16K thinking tokens, with diminishing returns beyond 32K. This budget sensitivity has important implications for deployment: operators can control the quality-cost tradeoff at serving time by setting maximum thinking token budgets. Models trained with RLVR learn to adapt their reasoning depth to the allocated budget — given fewer thinking tokens, the model compresses its reasoning to cover essential steps; given more tokens, it explores more alternatives and performs more thorough verification. This adaptive behaviour is a trained skill, not a free property of the base model, and emerges specifically from RL training on varied-difficulty problems where the optimal thinking depth differs across examples. The thinking token budget also interacts with problem difficulty: for easy problems, the model converges quickly regardless of budget, while for hard problems, accuracy continues to improve with budget up to the model's capability ceiling. A practical heuristic is to route queries through a difficulty classifier and assign thinking budgets proportional to estimated difficulty, reducing average inference cost by 40–60% compared to a fixed maximum budget for all queries.

import anthropic
import matplotlib.pyplot as plt
from typing import List, Tuple

client = anthropic.Anthropic()

BUDGETS = [1024, 4096, 8192, 16384, 32000]

def sweep_thinking_budgets(
    problem: str, budgets: List[int] = BUDGETS
) -> List[Tuple[int, str]]:
    results = []
    for budget in budgets:
        resp = client.messages.create(
            model="claude-opus-4-5",
            max_tokens=budget + 2000,
            thinking={"type": "enabled", "budget_tokens": budget},
            messages=[{"role": "user", "content": problem}],
        )
        thinking_len = sum(
            len(b.thinking.split()) for b in resp.content if b.type == "thinking"
        )
        answer = next((b.text for b in resp.content if b.type == "text"), "")
        print(f"budget={budget:6d}  thinking_words={thinking_len:5d}  answer={answer[:50]!r}")
        results.append((budget, answer))
    return results

Faithfulness of Extended Reasoning

A critical open question for extended CoT models is whether the visible reasoning trace is faithfully causally connected to the final answer, or whether the trace is a post-hoc rationalisation constructed to accompany an answer generated through a different process. Several lines of evidence suggest partial faithfulness at best. Interventions that alter intermediate steps in the thinking trace — replacing a correct step with an incorrect one — cause the final answer to change in 60–75% of cases, suggesting causal connection for many reasoning steps. However, counterfactual interventions that introduce deliberate errors often fail to propagate through the reasoning in the expected way: the model sometimes corrects the planted error in later steps without explicitly acknowledging it, suggesting that some error detection occurs through a mechanism not visible in the trace. Furthermore, extended reasoning models trained on mathematical problems show systematically worse calibration on out-of-distribution problem types where the trained reasoning patterns do not apply, and their confidence (expressed in the trace) does not correlate well with actual accuracy in these regimes. These findings suggest that extended CoT traces should be understood as a reasoning scaffold that improves accuracy without guaranteeing that every step is a faithful representation of the model's internal computation.

Faithfulness Limitation: Extended reasoning traces can contain confident but wrong steps — longer thinking does not guarantee correct reasoning, especially on problems requiring novel insights outside the training distribution. Models trained on competition mathematics extended CoT can produce fluent, confident-sounding traces that lead to incorrect final answers on problem types not well-represented in training data. Always verify final answers with an external verifier for high-stakes applications.

  • Thinking traces are partially faithful: step interventions affect final answers ~65% of the time
  • Self-correction phrases emerge from RL but do not always reflect genuine error detection
  • Confidence expressed in the trace does not correlate well with accuracy on OOD problem types
  • Longer traces improve accuracy but are not more faithful — additional length often includes exploratory dead ends

Distillation to Smaller Models

A key practical finding from DeepSeek-R1 and subsequent work is that extended reasoning capability can be distilled from large thinking models into smaller ones through standard supervised fine-tuning on (problem, extended-reasoning-trace, answer) triples generated by the large model. A 7B-parameter model fine-tuned on 800K such triples from DeepSeek-R1-671B achieves 50–60% of the teacher's AIME accuracy, substantially outperforming a 7B model trained from scratch with RLVR. This distillation efficiency has important implications: it suggests that extended reasoning patterns learned at scale can be transferred to smaller models that would not learn them efficiently through direct RL training, because the small model's exploration space is too limited to discover effective reasoning strategies independently. The distillation approach also dramatically reduces training cost: supervised fine-tuning on 800K examples requires roughly 100 GPU-hours for a 7B model, compared to thousands of GPU-hours for RLVR training of a model the same size. The main limitation of distillation is that the student is bounded by the teacher's capabilities and cannot generalise to problem types the teacher fails on. Combining distillation (for efficient knowledge transfer) with targeted RLVR fine-tuning (for capability extension on specific domains) is the recommended pipeline for organisations building smaller, cost-efficient reasoning models.

import torch
from datasets import Dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, TrainingArguments, Trainer
from typing import List, Dict

def build_distillation_dataset(traces: List[Dict]) -> Dataset:
    records = []
    for t in traces:
        text = "Problem: " + t["problem"] + " <think> " + t["thinking"] + " </think> " + t["answer"]
        records.append({"text": text})
    return Dataset.from_list(records)

def distill_thinking_model(
    base_model_id: str,
    traces: List[Dict],
    output_dir: str = "./distilled-thinker",
) -> None:
    tokenizer = AutoTokenizer.from_pretrained(base_model_id)
    model = AutoModelForCausalLM.from_pretrained(base_model_id, torch_dtype=torch.bfloat16)
    dataset = build_distillation_dataset(traces)
    def tokenize(ex):
        return tokenizer(ex["text"], truncation=True, max_length=4096, padding="max_length")
    tokenized = dataset.map(tokenize, batched=True)
    args = TrainingArguments(output_dir=output_dir, num_train_epochs=3,
                             per_device_train_batch_size=2, learning_rate=2e-5)
    Trainer(model=model, args=args, train_dataset=tokenized).train()

  • Students are bounded by teacher capabilities and cannot generalise beyond teacher failure modes
  • Combining distillation with targeted RLVR is the recommended pipeline for smaller reasoning models
  • Thinking trace quality matters more than quantity: 100K high-quality traces outperform 1M noisy ones

Key Takeaways

  • Extended CoT training enables accuracy on competition mathematics that standard CoT prompting cannot achieve regardless of model size
  • RLVR with binary correct/incorrect rewards on final answers is sufficient to train extended reasoning — no step-level supervision is required
  • Thinking token budgets control quality at serving time: routing difficult queries to larger budgets reduces average cost by 40-60%
  • Thinking traces are partially but not fully faithful — never rely on the trace alone as a correctness guarantee
  • Distillation of extended reasoning from large to small models is efficient and practical for cost-sensitive deployments
  • Emergent self-reflection behaviours (backtracking, error correction) arise from RLVR training as learned strategies, not as architectural features
