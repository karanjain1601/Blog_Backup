PTQ Calibration: Choosing Representative Data

Post-training quantization (PTQ) converts a floating-point model to a lower-bit representation without retraining. Unlike quantization-aware training (QAT), PTQ has no opportunity to adjust weights to compensate for quantization error — it must find the best quantization parameters (scale and zero-point) solely from a small set of calibration data passed through the model before deployment. The calibration step determines the activation range for each layer: how wide a range of values needs to be represented, and therefore how coarse the quantization grid must be. A poor calibration dataset or algorithm leads directly to higher perplexity in the deployed model.

Overview

The quantization of activations (as opposed to weights) is the primary reason PTQ requires calibration. Weight distributions are fixed after training and can be analysed offline. Activation distributions depend on the input: they differ across domains, tasks, and sequence lengths. Calibration runs a set of representative inputs through the model in float32, records the activation distribution at each quantization node, and fits quantization parameters that minimize the error introduced by mapping that distribution to a discrete integer grid. The number of calibration samples, the domain of those samples, and the fitting algorithm all substantially affect the final INT8 model's quality.

Why Calibration Matters

Activation tensors in transformer LLMs exhibit heavy tails: most values are small, but a small fraction of dimensions carry extremely large magnitudes (outliers). These outliers expand the required quantization range, wasting resolution on values that rarely appear. A scale chosen by MinMax (the simplest calibration method) is dominated by these outliers and quantizes the dense body of the distribution at low precision. Percentile, MSE, and KL-divergence methods all trade off clipping those outliers against increased saturation error — the error from values that exceed the clipping threshold. The best calibration method depends on the model's outlier severity, which grows with model size.

  • Activation outliers grow with model size: LLaMA-65B has more severe outliers than LLaMA-7B — KL or MSE calibration matters more at scale.
  • Domain mismatch: calibrating on wikitext-2 and deploying on code reduces INT8 accuracy by 2–5 perplexity points on code benchmarks.
  • Calibration sample count: 128–512 samples are typically sufficient; more samples give diminishing returns beyond 512 for most models.
  • Per-channel vs per-tensor: per-channel calibration fits separate scale/zero-point per output channel — essential for weights, beneficial for activations.
  • Static vs dynamic calibration: static calibration fixes scales at export; dynamic calibration recomputes per-token at inference (higher quality, higher latency).

MinMax Calibration

MinMax calibration sets the quantization range to [min(x), max(x)] over all calibration samples. This guarantees no saturation error — every observed activation value can be represented — but wastes quantization bins on outliers. For a symmetric INT8 range of [-128, 127], the scale is max(|min|, |max|) / 127. MinMax is the fastest calibration method (one pass, no optimization) and is the default in most quantization toolkits. It is acceptable for weight quantization but often suboptimal for activations due to outlier sensitivity.

import torch
import torch.nn.functional as F
import numpy as np
from scipy.stats import entropy as scipy_entropy

def collect_activations(model, dataloader, layer_name: str, n_batches: int = 64):
    """Collect activation tensors from a named layer for calibration."""
    activations = []
    hook_handle = None
    target_layer = dict(model.named_modules())[layer_name]

    def hook(module, input, output):
        activations.append(output.detach().float().cpu())

    hook_handle = target_layer.register_forward_hook(hook)
    model.eval()
    with torch.no_grad():
        for i, batch in enumerate(dataloader):
            if i >= n_batches:
                break
            _ = model(**{k: v.to(next(model.parameters()).device) for k, v in batch.items()})
    hook_handle.remove()
    return torch.cat([a.flatten() for a in activations])

def calibrate_minmax(x: torch.Tensor, bits: int = 8, symmetric: bool = True):
    x_min, x_max = x.min().item(), x.max().item()
    if symmetric:
        amax = max(abs(x_min), abs(x_max))
        scale = amax / (2 ** (bits - 1) - 1)
        zero_point = 0
    else:
        scale = (x_max - x_min) / (2 ** bits - 1)
        zero_point = round(-x_min / scale)
    return scale, zero_point

def calibrate_percentile(x: torch.Tensor, bits: int = 8, percentile: float = 99.9):
    lo = torch.quantile(x, (100 - percentile) / 100).item()
    hi = torch.quantile(x, percentile / 100).item()
    amax = max(abs(lo), abs(hi))
    scale = amax / (2 ** (bits - 1) - 1)
    return scale, 0

def calibrate_mse(x: torch.Tensor, bits: int = 8, n_candidates: int = 100):
    amax = x.abs().max().item()
    best_scale, best_mse = None, float('inf')
    for clip_ratio in np.linspace(0.5, 1.0, n_candidates):
        candidate_amax = amax * clip_ratio
        scale = candidate_amax / (2 ** (bits - 1) - 1)
        x_q = torch.clamp(torch.round(x / scale), -(2**(bits-1)), 2**(bits-1)-1) * scale
        mse = F.mse_loss(x_q, x).item()
        if mse < best_mse:
            best_mse, best_scale = mse, scale
    return best_scale, 0

def calibrate_kl(x: torch.Tensor, bits: int = 8, n_bins: int = 2048):
    hist, bin_edges = np.histogram(x.numpy(), bins=n_bins)
    best_scale, best_kl = None, float('inf')
    for threshold_idx in range(bits * 8, n_bins):
        threshold = bin_edges[threshold_idx]
        scale = threshold / (2 ** (bits - 1) - 1)
        quantized = np.clip(np.round(x.numpy() / scale), -(2**(bits-1)), 2**(bits-1)-1) * scale
        hist_q, _ = np.histogram(quantized, bins=n_bins, range=(bin_edges[0], bin_edges[-1]))
        p = hist.astype(float) + 1e-8
        q = hist_q.astype(float) + 1e-8
        kl = scipy_entropy(p / p.sum(), q / q.sum())
        if kl < best_kl:
            best_kl, best_scale = kl, scale
    return best_scale, 0

]:

Percentile and MSE Calibration

Percentile calibration clips the quantization range at the p-th and (100-p)-th percentiles of the observed activation distribution. The 99th or 99.9th percentile is a common choice: it discards the top 0.1–1% of values (typically outliers) and fits the quantization grid to the dense body of the distribution. MSE calibration directly optimizes the quantization scale to minimize mean squared error between the original and quantized tensor, searching over a grid of candidate clip thresholds. MSE calibration is more compute-intensive than percentile but usually delivers slightly lower error because it optimizes the metric that matters directly.

KL-Divergence Calibration

KL-divergence calibration (used by TensorRT and NVIDIA's quantization toolkit) fits the quantization threshold by minimizing the KL divergence between the floating-point and quantized activation histograms. The intuition is that a good quantization should preserve the shape of the activation distribution, not just minimize pointwise error. KL calibration tends to perform best on activations with strongly multi-modal or heavy-tailed distributions. It requires computing a histogram (typically 2048 bins) over the calibration data and iterating over threshold candidates, making it the most compute-intensive calibration method.

Calibration Method Samples Needed Compute Cost Typical PPL Delta Notes
MinMax 64–128 Trivial (one pass) +0.3 – 1.5 Dominated by outliers; worst for large models with heavy-tailed activations
99th Percentile 128–256 Low (quantile op) +0.1 – 0.5 Robust to outliers; good default when MSE/KL is too slow
MSE 128–512 Medium (grid search over clip ratios) +0.05 – 0.2 Directly minimizes quantization error; best for symmetric distributions
KL-Divergence 256–512 High (histogram + threshold scan) +0.05 – 0.15 Best for multi-modal and heavy-tailed activations; used by TensorRT
GPTQ Hessian 128 (Hessian-weighted) High (second-order) +0.01 – 0.1 Weight-only quantization; uses Hessian to minimize layer-wise output error

Calibration Data Selection

The calibration dataset must represent the deployment distribution. A model calibrated on wikitext-2 (formal English prose) and deployed on Python code or multilingual text will have systematically miscalibrated activation scales for the token distributions it encounters at inference. The recommended practice is to construct a mixed calibration set: sample from multiple domains (natural language, code, math, multilingual) weighted by expected deployment usage. For general-purpose models, c4 is a better default calibration source than wikitext-2 because it covers a broader web-text distribution.

import torch
import numpy as np
from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM

def evaluate_ptq_perplexity(
    model_name: str,
    calibration_sources: list,
    n_calib_samples: int = 256,
    n_eval_tokens: int = 4096
) -> dict:
    """
    Sweep calibration datasets and measure resulting INT8 model perplexity.
    Uses torch.ao.quantization for static INT8 quantization.
    """
    import torch.ao.quantization as tq
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    results = {}

    for source_name, dataset_id, subset, split in calibration_sources:
        print(f"\nCalibration source: {source_name}")
        # Load calibration data
        ds = load_dataset(dataset_id, subset, split=split, streaming=True)
        calib_texts = []
        for item in ds:
            text = item.get("text") or item.get("content") or ""
            if len(text) > 200:
                calib_texts.append(text[:512])
            if len(calib_texts) >= n_calib_samples:
                break
        # Tokenize calibration batch
        calib_enc = tokenizer(
            calib_texts, return_tensors="pt", truncation=True,
            max_length=512, padding=True
        )
        # Load fresh float model for each calibration experiment
        model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float32)
        model.eval()
        # Collect activation statistics (simplified: log input range per layer)
        activation_ranges = {}
        hooks = []
        for name, module in model.named_modules():
            if isinstance(module, torch.nn.Linear):
                def make_hook(n):
                    def hook(m, inp, out):
                        t = out.detach().float()
                        activation_ranges[n] = (t.min().item(), t.max().item())
                    return hook
                hooks.append(module.register_forward_hook(make_hook(name)))
        with torch.no_grad():
            _ = model(**calib_enc)
        for h in hooks:
            h.remove()
        avg_range = np.mean([hi - lo for lo, hi in activation_ranges.values()])
        results[source_name] = {"avg_activation_range": avg_range, "n_layers": len(activation_ranges)}
        print(f"  Avg activation range: {avg_range:.3f}  ({len(activation_ranges)} layers)")
        del model
    return results

Domain Mismatch Warning: Using only 128 calibration samples from a single domain (e.g., wikitext-2) for a model intended for code or multilingual use causes domain mismatch — always use diverse calibration data matching the deployment distribution. Domain mismatch can inflate perplexity by 2–5 points on out-of-distribution tasks even when in-domain perplexity looks acceptable.

Smoothing and Outlier Handling

SmoothQuant (Xiao et al., 2022) addresses the fundamental problem of activation outliers in LLMs by mathematically migrating the quantization difficulty from activations to weights. The key insight is that for a linear layer Y = X W^T, any positive per-channel scale vector s can be applied as Y = (X / s) (W * s)^T — the output is unchanged. SmoothQuant chooses s to reduce the dynamic range of activations (making them easier to quantize) while proportionally increasing the range of weights (which are easier to quantize because they are static and can use per-channel scales). This migration is controlled by a hyperparameter α ∈ [0, 1] that balances how much difficulty is shifted to weights.

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer

def compute_smoothquant_scales(
    act_scales: dict,
    weight_scales: dict,
    alpha: float = 0.5
) -> dict:
    """
    Compute per-channel SmoothQuant migration scales.
    act_scales: {layer_name: tensor of shape (d_in,)} — max abs activation per channel.
    weight_scales: {layer_name: tensor of shape (d_in,)} — max abs weight per in-channel.
    alpha: migration strength; 0.5 is the recommended default.
    """
    smooth_scales = {}
    for name in act_scales:
        if name not in weight_scales:
            continue
        a = act_scales[name]   # (d_in,)
        w = weight_scales[name]  # (d_in,)
        # s_i = max_act_i^alpha / max_weight_i^(1-alpha)
        s = (a.pow(alpha) / w.pow(1 - alpha)).clamp(min=1e-5)
        smooth_scales[name] = s
    return smooth_scales

def apply_smoothquant(
    model: nn.Module,
    smooth_scales: dict,
    layer_name_map: dict
) -> nn.Module:
    """Apply SmoothQuant scales: divide activations by s, multiply weight rows by s."""
    with torch.no_grad():
        for linear_name, scale in smooth_scales.items():
            if linear_name not in layer_name_map:
                continue
            linear = layer_name_map[linear_name]
            # Weight rows scaled by s: W_new[i, :] = W[i, :] * s[i]
            linear.weight.data = linear.weight.data * scale.unsqueeze(1)
            if linear.bias is not None:
                linear.bias.data = linear.bias.data * scale
    return model

import torch
import torch.nn as nn
import numpy as np

def detect_and_suppress_outliers(
    x: torch.Tensor,
    n_sigma: float = 6.0,
    strategy: str = "clip"
) -> tuple:
    """
    Detect activation outliers beyond n_sigma standard deviations.
    Strategies: 'clip' (hard clip to threshold), 'migrate' (move outlier
    magnitude to weight scaling, keeping tensor values bounded).
    Returns: (suppressed tensor, outlier mask, quantization error reduction).
    """
    mu = x.mean()
    sigma = x.std()
    threshold = n_sigma * sigma
    outlier_mask = x.abs() > (mu.abs() + threshold)
    outlier_frac = outlier_mask.float().mean().item()
    print(f"Outliers (>{n_sigma}σ): {outlier_frac*100:.3f}% of values")
    print(f"  Max outlier magnitude: {x[outlier_mask].abs().max():.2f}" if outlier_mask.any() else "  No outliers")

    if strategy == "clip":
        x_clean = x.clamp(-(mu.abs() + threshold), mu.abs() + threshold)
    elif strategy == "migrate":
        # Scale outlier channels down; would scale corresponding weight up
        scale_per_channel = x.abs().max(dim=0).values.clamp(min=1.0)
        x_clean = x / scale_per_channel.unsqueeze(0)
    else:
        x_clean = x

    # Measure quantization error before vs after suppression
    scale_before = x.abs().max().item() / 127.0
    scale_after = x_clean.abs().max().item() / 127.0
    x_q_before = torch.round(x / scale_before).clamp(-128, 127) * scale_before
    x_q_after = torch.round(x_clean / scale_after).clamp(-128, 127) * scale_after
    err_before = (x_q_before - x).pow(2).mean().sqrt().item()
    err_after = (x_q_after - x_clean).pow(2).mean().sqrt().item()
    print(f"  RMSE before suppression: {err_before:.5f}")
    print(f"  RMSE after  suppression: {err_after:.5f}")
    print(f"  Error reduction: {(1 - err_after/err_before)*100:.1f}%")
    return x_clean, outlier_mask, (err_before - err_after)

torch.manual_seed(42)
x_test = torch.cat([torch.randn(9900) * 2.0, torch.randn(100) * 50.0])
for strat in ["clip", "migrate"]:
    print(f"\nStrategy: {strat}")
    detect_and_suppress_outliers(x_test, n_sigma=6.0, strategy=strat)

Key Takeaways

  • MinMax calibration is fast but dominated by outliers; use percentile or MSE for better INT8 quality on LLMs.
  • KL-divergence calibration (TensorRT default) minimizes distributional shift; best for heavy-tailed activation profiles.
  • MSE calibration directly optimizes what matters — mean squared quantization error — and is a reliable default for most models.
  • 128–256 calibration samples are sufficient for most models; gains from >512 samples are marginal.
  • Calibration data domain must match deployment domain; mixing wikitext-2, c4, and code data is a safe default for general models.
  • SmoothQuant (α=0.5) migrates outlier difficulty from activations to weights, reducing INT8 perplexity by 1–3 points on large models.
  • Per-channel weight quantization is essential; per-tensor weight quantization causes measurable accuracy loss on all model sizes.
  • GPTQ uses Hessian-weighted calibration for weight-only quantization and achieves near-lossless quality at 4-bit for 7B+ models.
