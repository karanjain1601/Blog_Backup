Reward Models and Verifiers for Test-Time Search

Reward models and verifiers unlock test-time compute scaling: given N candidate solutions sampled from an LLM, a scoring function ranks them and returns the best. This simple idea — best-of-N — dramatically improves accuracy on math and coding benchmarks, with gains compounding as N grows. The scoring function can be a trained neural reward model (ORM or PRM) or a deterministic rule-based verifier.

Outcome Reward Models (ORM)

An Outcome Reward Model (ORM) takes the complete (prompt, response) pair and outputs a scalar reward. ORMs are trained on human preference pairs or binary correctness labels. During best-of-N, all N candidates are scored and the highest-scoring one is returned. Training is simpler than for PRMs but ORMs provide no signal about which intermediate reasoning steps were incorrect or misleading.

from transformers import AutoTokenizer, AutoModelForSequenceClassification\nimport torch\n\ndef best_of_n_orm(prompt, candidates, model_name="orm-checkpoint"):\n    tok = AutoTokenizer.from_pretrained(model_name)\n    model = AutoModelForSequenceClassification.from_pretrained(model_name)\n    model.eval()\n    scores = []\n    for solution in candidates:\n        inp = tok(prompt + solution, return_tensors="pt", truncation=True, max_length=2048)\n        with torch.no_grad():\n            score = model(**inp).logits[0, 0].item()\n        scores.append(score)\n    best_idx = max(range(len(scores)), key=lambda i: scores[i])\n    return candidates[best_idx], scores

ORM training typically uses a ranking loss such as Bradley-Terry or pairwise cross-entropy. A common recipe: fine-tune a pretrained language model with a scalar head on chosen/rejected pairs from RLHF pipelines. For math tasks, synthetic correctness labels — comparing parsed answers to ground truth — offer cheap, scalable supervision without requiring expensive human annotators for every solution pair.

Process Reward Models (PRM)

A Process Reward Model (PRM) scores each intermediate reasoning step rather than only the final answer. Step-level rewards provide a richer training signal and enable tree-search algorithms like MCTS and beam search to prune unpromising branches early. PRMs correlate more strongly with mathematical correctness than ORMs, but collecting step-level human annotations is expensive and time-consuming.

from math import prod\nimport torch\n\ndef score_with_prm(prompt, solution, prm, tok):\n    steps = [s for s in solution.strip().splitlines() if s.strip()]\n    step_scores = []\n    context = prompt\n    for step in steps:\n        inp = tok(context + " " + step, return_tensors="pt", truncation=True, max_length=2048)\n        with torch.no_grad():\n            score = prm(**inp).logits[0, 0].sigmoid().item()\n        step_scores.append(score)\n        context += " " + step\n    overall = prod(step_scores) if step_scores else 0.0\n    return overall, step_scores

PRM800K (Lightman et al., 2023) is the foundational dataset: human annotators labeled each step of GPT-4 math solutions as positive, neutral, or negative. A PRM trained on this data significantly outperformed an ORM at equivalent test-time compute. The key insight: detecting a flawed step early avoids wasting compute on continuations of an already-incorrect reasoning chain.

Rule-Based Verifiers

For domains with closed-form correct answers — arithmetic, algebra, competitive programming — rule-based verifiers provide perfect signal with zero training cost. A math verifier parses the model boxed answer and checks symbolic equality with a CAS. A code verifier runs unit tests. These deterministic oracles cannot be gamed by a policy model tuning outputs to fool a learned scorer.

from sympy import simplify, sympify\nimport re\n\ndef math_verifier(output: str, truth: str) -> int:\n    # Return 1 if model answer matches truth, 0 otherwise\n    if "boxed{" not in output:\n        return 0\n    try:\n        # pull content from boxed{...} tag\n        ans = output.split("boxed{")[1].split("}")[0].strip()\n        a = sympify(ans)\n        b = sympify(truth)\n        return int(simplify(a - b) == 0)\n    except Exception:\n        return 0

Rule-based verifiers are the backbone of modern RL training loops for reasoning models. DeepSeek-R1 and related systems combine format rewards (did the model use the expected output tags?) with accuracy rewards (is the parsed answer correct?). This hybrid signal trains models to reason in a structured, parseable format without requiring any neural reward model at inference time.

Best-of-N Sampling

Best-of-N sampling is the simplest test-time search strategy: sample N solutions independently with temperature > 0, score each with a verifier or reward model, and return the highest-scoring one. Accuracy scales as 1-(1-p)^N where p is per-sample pass rate. The strategy is embarrassingly parallel — all candidates can be generated and scored simultaneously — making it straightforward to scale.

def best_of_n(prompt, model, tokenizer, reward_fn, n=16, temp=0.8):\n    inputs = tokenizer(prompt, return_tensors="pt")\n    candidates = []\n    for _ in range(n):\n        out = model.generate(\n            **inputs, do_sample=True, temperature=temp, max_new_tokens=512\n        )\n        text = tokenizer.decode(out[0], skip_special_tokens=True)\n        candidates.append(text[len(prompt):])\n    scores = [reward_fn(prompt, c) for c in candidates]\n    ranked = sorted(zip(scores, candidates), reverse=True)\n    best_score, best_sol = ranked[0]\n    print(f"Scores: min={ranked[-1][0]:.3f} max={best_score:.3f}")\n    return best_sol

Beam Search with PRM

Beam search with a PRM maintains a fixed-width beam of partial solutions. At each reasoning step, K continuations are sampled per beam element, scored by the PRM, and only the top-B partial solutions survive. This focuses compute on the most promising reasoning paths rather than sampling complete solutions independently, achieving higher accuracy per unit of compute for long multi-step problems.

warning: ORMs are susceptible to reward hacking — a model can produce a plausible-looking final answer with flawed reasoning steps. PRMs mitigate this but require expensive step-level human annotations to train.

In practice, tree search with a PRM pays off most when reasoning chains are long and N is large. For short problems or small N, best-of-N with a strong ORM is simpler and nearly as effective. MCTS-style approaches — maintaining visit counts and value estimates per node — further improve quality but add significant engineering complexity and remain sensitive to PRM score calibration.

Key Takeaways

  • ORMs score final (prompt, response) pairs and are cheap to train but susceptible to reward hacking when used for RL fine-tuning or repeated sampling.
  • PRMs assign per-step rewards, enabling beam search and MCTS; PRM800K showed that step-level supervision strongly predicts mathematical problem-solving accuracy.
  • Rule-based verifiers (symbolic math checks, unit test runners) provide zero-cost, unhackable reward signal for domains with deterministic correct answers.
  • Best-of-N accuracy follows 1-(1-p)^N; gains are consistent but diminishing — use a strong verifier to maximize the value of each sampled candidate.
  • Beam search with a PRM achieves better accuracy per unit compute than best-of-N for long reasoning chains by pruning low-probability paths early in the generation process.
  • Choose the verifier to match the task: rule-based for math and code, ORM for short-form candidate ranking, PRM for long-chain reasoning, LLM-as-judge for open-ended quality assessment.

Start with a rule-based verifier if your task allows it — zero training cost and no reward hacking. For broader generalization, train an ORM on correctness labels first; add a PRM only if ORM-based search plateaus. Reserve LLM-as-judge for open-ended tasks where symbolic verification is impossible, and cross-validate judge scores against human labels before deploying at scale.
