GPTQ: Post-Training Quantization via Optimal Brain Compression

GPTQ (Generative Pre-trained Transformer Quantization) is a post-training quantization algorithm introduced in the 2023 paper 'GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers' by Frantar et al. It adapts the Optimal Brain Compression (OBC) framework to efficiently quantize large language models to INT4 or INT3 with minimal perplexity degradation. Unlike naive round-to-nearest quantization, GPTQ uses the second-order curvature of the loss function (approximated by the Hessian of the layer's reconstruction loss) to intelligently distribute quantization error across weights. The result is that GPTQ can quantize a 175-billion-parameter GPT-3 model to 4 bits in approximately four GPU-hours—a task that would be computationally prohibitive with methods requiring Hessian computation for the entire model simultaneously. The key enabling insight is layer-wise quantization: each transformer block's linear layers are quantized independently, in sequence, making the problem tractable.

Overview

The intellectual lineage of GPTQ traces back to the Optimal Brain Surgeon (OBS) and Optimal Brain Damage (OBD) work from the 1990s on network pruning. OBS showed that the optimal perturbation to compensate for removing a single weight is a rank-1 update to all remaining weights, derived from the inverse Hessian of the loss. GPTQ applies this principle to quantization: when a weight is rounded to its nearest integer representation, the resulting quantization error is a perturbation. GPTQ propagates this error through the remaining unquantized weights using the inverse Hessian, ensuring the reconstructed output of the layer matches the full-precision output as closely as possible. Because each layer is processed independently (using the input activations from the previous layer as a proxy for the full loss Hessian), GPTQ avoids the intractable cost of computing the full-model Hessian while still achieving remarkably low reconstruction error.

  • Layer-wise quantization: each linear layer is quantized independently, column by column
  • Hessian approximation: H = X^T X / N, where X is the calibration activation matrix
  • Cholesky trick: precompute a triangular factorization to efficiently extract H^{-1} rows
  • Error propagation: after quantizing column i, update columns i+1...d_in with H^{-1} correction
  • Group quantization: divide d_in columns into groups of size g; use one scale per group
  • Supports 2-bit, 3-bit, and 4-bit targets; 4-bit g=128 is the standard production configuration

OBC and Layer-wise Quantization

Optimal Brain Compression reformulates weight quantization as a constrained optimization problem: find the quantized weight Q that minimizes the squared difference between the full-precision and quantized layer outputs E = ||WX − QX||^2, where X is the matrix of calibration activations. Expanding this gives E = (W − Q) H (W − Q)^T, where H = XX^T / N is the Hessian of the layer reconstruction loss with respect to the weight rows. Minimizing E subject to each element of Q being constrained to the integer grid is an NP-hard combinatorial problem in general. OBC solves a relaxation by processing one column (or weight) at a time, quantizing it, then updating the remaining weights to compensate for the introduced error. This greedy, sequential approach turns the intractable joint problem into a series of tractable scalar quantization steps.

The key mathematical result is that, after quantizing weight w_{i,j} and introducing error e = w_{i,j} − q_{i,j}, the optimal update to all remaining unquantized weights in the same row is: Δw_{i,k} = −e × H^{-1}{j,k} / H^{-1} update across multiple columns and achieving good GPU utilization.} for all k > j. This update steers the remaining weights to compensate for the quantization error of column j, as measured by the Hessian metric. The denominator H^{-1}_{j,j} normalizes by the curvature at position j. GPTQ extends OBC from single-weight to block-column processing for GPU efficiency: it quantizes a block of B columns simultaneously (B=128 is typical), amortizing the cost of the H^{-1

The Cholesky Factorization Trick

Computing H^{-1} directly requires O(d_in^3) operations and O(d_in^2) memory, which for d_in = 4096 (a typical transformer hidden size) means solving a 4096×4096 system—manageable but not free. More importantly, GPTQ needs only the rows of H^{-1} sequentially (row j when quantizing column j), making it wasteful to compute and store all of H^{-1} upfront. The Cholesky factorization trick avoids this: H is factored as H = L L^T once (O(d_in^3) but done once), and then each required row of H^{-1} can be obtained from the Cholesky factor by solving a triangular system—O(d_in^2) total for all rows. Additionally, working with the Cholesky factor provides numerical stability: it degenerates gracefully when H is rank-deficient (because the calibration set did not activate all directions), whereas naive inversion would produce NaN or infinite values. A small damping constant (typically 1% of the mean diagonal of H) is added before factorization for robustness.

import numpy as np

def gptq_quantize_layer(W, X, bits=4):
    """GPTQ: quantize weight matrix W using Hessian H = X^T X / N."""
    d_out, d_in = W.shape
    W_q = W.copy()
    H = X.T @ X / X.shape[0]          # Hessian approximation (d_in, d_in)
    H += np.eye(d_in) * 1e-6          # damping for numerical stability
    # Cholesky factorization for stable H^{-1} computation
    L = np.linalg.cholesky(H + np.eye(d_in) * 1e-4)
    L_inv = np.linalg.solve(L, np.eye(d_in))
    H_inv = L_inv.T @ L_inv            # inverse Hessian
    q_min, q_max = -(2 ** (bits - 1)), 2 ** (bits - 1) - 1
    for col in range(d_in):
        w_col = W_q[:, col]
        scale = max((w_col.max() - w_col.min()) / (q_max - q_min), 1e-8)
        w_q = np.clip(np.round(w_col / scale), q_min, q_max) * scale
        err = (w_col - w_q).reshape(-1, 1)   # quantization error (d_out, 1)
        # Propagate error to remaining columns using H^{-1} row
        if col + 1 < d_in:
            h_ratio = H_inv[col, col+1:] / H_inv[col, col]
            W_q[:, col+1:] -= err @ h_ratio.reshape(1, -1)
        W_q[:, col] = w_q
    return W_q

np.random.seed(0)
W = np.random.randn(256, 512).astype(np.float32) * 0.02
X = np.random.randn(128, 512).astype(np.float32)
W_q = gptq_quantize_layer(W, X, bits=4)
rmse = np.sqrt(np.mean((W - W_q) ** 2))
print(f"GPTQ RMSE (4-bit): {rmse:.6f}")
print(f"Weight range  : [{W.min():.4f}, {W.max():.4f}]")
print(f"Quantized range: [{W_q.min():.4f}, {W_q.max():.4f}]")

The numpy implementation above demonstrates the core algorithm on a small matrix for clarity. The actual AutoGPTQ implementation processes columns in blocks of 128 for GPU efficiency, uses CUDA kernels for the matrix updates, and handles the group quantization of scales separately from the column-by-column error propagation. The critical insight visible in the code is that the error correction on line 'W_q[:, col+1:] -= err @ h_ratio.reshape(1, -1)' performs a rank-1 update to all remaining columns simultaneously—this is the step that makes GPTQ dramatically more accurate than round-to-nearest quantization, especially for the early-quantized columns whose errors would otherwise compound.

Quantizing to INT4

INT4 quantization uses only 16 distinct values per weight, making the quantization grid coarse enough that naive rounding introduces substantial error for any weight distribution with non-negligible variance. For a zero-mean Gaussian weight with standard deviation σ ≈ 0.02 (typical for a trained transformer), the INT4 grid spacing (scale) is approximately 2σ × 15/7 ≈ 0.086, meaning every weight is displaced by up to 0.043—more than twice the standard deviation. Without error correction, this level of perturbation would cause catastrophic degradation for models above about 1 billion parameters. GPTQ's error propagation mitigates this by ensuring that the reconstructed layer output—not the individual weights—is close to the full-precision output. The quantization errors in individual weights partially cancel each other out, and the remaining error is distributed across weights in a way that minimizes its effect on the output.

In practice, 4-bit GPTQ with group size 128 achieves perplexity within 0.3–0.5 points of the FP16 baseline on WikiText-2 for 7B and 13B parameter Llama-2 models, dropping to within 0.1 points for models above 30B parameters. The accuracy improvement with model size reflects the over-parameterization effect: larger models have more redundancy, making them more tolerant of weight perturbations. For very small models (under 1B parameters) or for tasks requiring precise numerical reasoning (arithmetic, coding), INT4 quantization can cause noticeable degradation even with GPTQ's error correction, and INT8 or even FP16 should be preferred.

Group Quantization

Group quantization addresses a fundamental limitation of per-channel scales: for a weight matrix of shape (d_out, d_in), per-channel quantization uses one scale per row (d_out scales), but within each row the d_in weights still share a single scale. If a single row of weights has a bimodal distribution—with small weights clustered near zero and a few large outliers—the single per-row scale is forced to cover the full range, wasting resolution on the ordinary weights. Group quantization divides each row into groups of g consecutive columns, assigning one scale per group. With g=128 and d_in=4096, each row gets 32 scales instead of 1, reducing quantization error significantly at the cost of 32 additional scale values per row. The scale overhead in memory is: (d_out × d_in / g) × sizeof(fp16) bytes, which is typically 1–10% of the compressed weight size—a worthwhile trade for the accuracy gain.

import numpy as np

def quantize_grouped(W, bits=4, group_size=128):
    """Quantize W with independent scale per column-group."""
    d_out, d_in = W.shape
    W_q = np.zeros_like(W)
    q_min, q_max = -(2 ** (bits - 1)), 2 ** (bits - 1) - 1
    for g0 in range(0, d_in, group_size):
        g1 = min(g0 + group_size, d_in)
        grp = W[:, g0:g1]
        scale = (grp.max(axis=1, keepdims=True) - grp.min(axis=1, keepdims=True))
        scale = np.where(scale < 1e-8, 1e-8, scale) / (q_max - q_min)
        W_q[:, g0:g1] = np.clip(np.round(grp / scale), q_min, q_max) * scale
    return W_q

np.random.seed(42)
W = np.random.randn(256, 4096).astype(np.float32) * 0.02

for gs in [32, 128, 1024, 4096]:
    W_q = quantize_grouped(W, bits=4, group_size=gs)
    rmse = np.sqrt(np.mean((W - W_q) ** 2))
    n_groups = 256 * (4096 // gs)
    overhead_bytes = n_groups * 2   # fp16 scale per group
    weight_bytes   = 256 * 4096 * 4 / 8   # 4-bit packed
    overhead_ratio = overhead_bytes / weight_bytes
    print(f"group_size={gs:5d}  RMSE={rmse:.6f}  scale_overhead={overhead_ratio:.3f}x")

Using AutoGPTQ

AutoGPTQ is the standard library for applying GPTQ quantization to Hugging Face-compatible causal language models. It handles the calibration data loading, layer-by-layer GPTQ application, scale packing, and safetensors serialization automatically. The most important configuration parameters are: bits (4 is standard, 3 is aggressive), group_size (128 is the default; 64 or 32 give better accuracy at higher storage overhead), damp_percent (controls Hessian regularization; 0.01 is usually fine), and desc_act (whether to sort columns by decreasing Hessian diagonal before quantizing, which can improve accuracy by ~0.1 PPL at the cost of 2–4× longer quantization time). The calibration dataset should be tokenized sequences of the model's maximum context length (2048 or 4096 tokens), not short snippets—the Hessian quality depends on seeing realistic activation patterns.

from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig
from transformers import AutoTokenizer
from datasets import load_dataset
import torch, os

model_name = "meta-llama/Llama-2-7b-hf"
tokenizer = AutoTokenizer.from_pretrained(model_name, use_fast=True)

quant_config = BaseQuantizeConfig(
    bits=4,
    group_size=128,
    damp_percent=0.01,
    desc_act=False,     # True gives better accuracy but much slower quantization
)

# Calibration dataset: 128 samples from C4
dataset = load_dataset("c4", "en", split="train", streaming=True)
examples = []
for i, row in enumerate(dataset):
    if i >= 128: break
    enc = tokenizer(row["text"], return_tensors="pt", max_length=512, truncation=True)
    examples.append(enc)

model = AutoGPTQForCausalLM.from_pretrained(model_name, quant_config)
model.quantize(examples)

save_dir = "./llama-2-7b-gptq-4bit-g128"
model.save_quantized(save_dir, use_safetensors=True)
tokenizer.save_pretrained(save_dir)

size_gb = sum(
    os.path.getsize(os.path.join(save_dir, f))
    for f in os.listdir(save_dir)
    if f.endswith((".safetensors", ".bin"))
) / 1e9
print(f"Saved to: {save_dir}")
print(f"Quantized size: {size_gb:.2f} GB  (FP16 baseline ~13 GB)")

Info: GPTQ processes each layer independently and can be parallelized across layers, making quantization of 70B models feasible in hours on a single GPU with enough RAM. A 70B model requires roughly 140 GB of FP16 storage, which fits on an 8×A100-80GB server. AutoGPTQ supports multi-GPU quantization via the --num_workers flag. Quantization speed scales with d_in^3 per layer (Cholesky cost), so 70B models with d_in=8192 take approximately 64× longer per layer than 7B models with d_in=4096—expect 6–12 hours on a single A100.

Performance and Tradeoffs

GPTQ-quantized models served through AutoGPTQ's CUDA kernels or exllama2 achieve 2–4× higher token throughput than FP16 models on the same GPU, primarily because the INT4 weights fit in fewer cache lines and require less memory bandwidth during the memory-bound decode phase of autoregressive generation. The decode phase is bottlenecked by reading model weights from GPU memory for each generated token; halving the weight size (FP16 → INT4) approximately halves the time spent on weight reads, translating directly to higher tokens-per-second. Prefill throughput (processing the input prompt) benefits less because it is compute-bound, not memory-bound—the INT4 weights must be dequantized to FP16 before matrix multiplication, adding a small overhead.

from auto_gptq import AutoGPTQForCausalLM
from transformers import AutoTokenizer, GenerationConfig
import torch, time

model_dir = "./llama-2-7b-gptq-4bit-g128"
tokenizer = AutoTokenizer.from_pretrained(model_dir, use_fast=True)

model = AutoGPTQForCausalLM.from_quantized(
    model_dir,
    use_safetensors=True,
    device="cuda:0",
    inject_fused_attention=True,
)
model.eval()

prompt = "Explain the Cholesky decomposition trick used in GPTQ quantization:"
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")
gen_cfg = GenerationConfig(max_new_tokens=200, do_sample=False)

t0 = time.perf_counter()
with torch.no_grad():
    output = model.generate(**inputs, generation_config=gen_cfg)
elapsed = time.perf_counter() - t0

n_new = output.shape[1] - inputs["input_ids"].shape[1]
tps = n_new / elapsed
mem_gb = torch.cuda.memory_allocated() / 1e9
print(f"Generated {n_new} tokens in {elapsed:.2f}s ({tps:.1f} tok/s)")
print(f"GPU memory: {mem_gb:.2f} GB")
print(tokenizer.decode(output[0], skip_special_tokens=True))
  • 4-bit GPTQ reduces 7B model GPU memory from ~13 GB (FP16) to ~4 GB (INT4 g=128)
  • Decode throughput improves 2–4× over FP16 due to reduced memory bandwidth pressure
  • desc_act=True improves perplexity by ~0.1 PPL but increases quantization time 2–4×
  • Smaller group sizes (g=32) improve accuracy but increase model file size by ~15%
  • exllama2 backend gives 30–50% faster inference than the default triton backend
  • 3-bit GPTQ is viable for models above 13B parameters; below that, quality drops sharply

Key Takeaways

  • GPTQ applies Optimal Brain Compression layer-by-layer, making 175B+ quantization tractable
  • The Hessian H = X^T X / N captures how sensitive the layer output is to each weight
  • Error propagation via H^{-1} corrects downstream weights after each column is quantized
  • Group size 128 is the standard production setting: good accuracy with modest size overhead
  • 4-bit GPTQ achieves <0.5 PPL degradation on 7B+ models vs FP16 on WikiText-2
  • AutoGPTQ + exllama2 gives 2–4× decode speedup and 3× memory reduction vs FP16
  • Calibration quality matters: use 128 samples of full-context-length sequences, not short text
  • GPTQ is the right choice when you can afford offline quantization time for maximum accuracy
