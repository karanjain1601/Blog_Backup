Mixed-Precision Quantization

  • description: Assigning different bit-widths to different layers or attention heads based on sensitivity analysis, achieving better accuracy-compression tradeoffs than uniform quantization.
  • topic: deep-learning
  • status: published
  • updated: 2026-07-10

Mixed-Precision Quantization

Mixed-precision quantization assigns different numerical formats to different parts of a model — some layers at INT8, others at INT4, and the most sensitive at FP16 — rather than applying a single bit-width uniformly. This layer-heterogeneous approach recognizes that quantization sensitivity varies dramatically across a transformer: early embedding layers, the final language model head, and certain attention layers are far more sensitive to bit-width reduction than the bulk of feed-forward layers. By protecting the most sensitive layers and aggressively compressing the least sensitive, mixed-precision quantization achieves a better accuracy-compression Pareto frontier than any single uniform bit-width.

Overview

The central challenge in mixed-precision quantization is deciding which layers get which bit-width. This bit-width assignment problem is exponential in the number of layers: a 32-layer model with three choices per layer (INT4, INT8, FP16) has 3^32 ≈ 1.85 × 10^15 possible assignments. Practical methods fall into three categories: (1) sensitivity-based pruning — rank layers by quantization sensitivity and apply a threshold; (2) search-based methods — evolutionary algorithms or reinforcement learning to explore the assignment space guided by a quality metric; (3) algorithmic methods — LLM.int8() and AQLM, which derive mixed precision from the structure of the weight or activation tensors themselves. Each approach has different computational cost and optimality guarantees.

Layer Sensitivity Analysis

Sensitivity analysis quantifies how much quantizing each layer individually degrades the model's output quality. The simplest proxy is the Taylor expansion of the loss: the sensitivity of layer l is approximated as |∂L/∂W_l ⊙ W_l|, the element-wise product of gradients and weights summed over all parameters in that layer. Layers with high sensitivity — typically the first and last layers, layers in early transformer blocks, and attention output projections — receive higher bit-widths. Layers with low sensitivity — typically the middle feed-forward layers — receive aggressive quantization. This proxy is computed in a single backward pass and scales to very large models.

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer
from dataclasses import dataclass
from typing import Dict, List

@dataclass
class LayerSensitivity:
    name: str
    sensitivity: float
    n_params: int
    assigned_bits: int = 8

def compute_taylor_sensitivity(
    model_name: str,
    calib_text: str,
    high_bits: int = 8,
    low_bits: int = 4,
    sensitivity_threshold: float = 0.5
) -> List[LayerSensitivity]:
    """
    Rank linear layers by Taylor sensitivity |grad * weight|.
    Layers above sensitivity_threshold (relative) get high_bits;
    layers below get low_bits.
    """
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float32)
    model.eval()
    # Forward + backward pass to get gradients
    inputs = tokenizer(calib_text, return_tensors="pt", truncation=True, max_length=256)
    input_ids = inputs["input_ids"]
    outputs = model(input_ids=input_ids, labels=input_ids)
    loss = outputs.loss
    loss.backward()
    # Compute Taylor sensitivity per linear layer
    sensitivities = []
    for name, module in model.named_modules():
        if not isinstance(module, nn.Linear):
            continue
        if module.weight.grad is None:
            continue
        # |grad * weight| summed — Taylor expansion proxy
        s = (module.weight.grad * module.weight.data).abs().sum().item()
        sensitivities.append(LayerSensitivity(
            name=name, sensitivity=s, n_params=module.weight.numel()
        ))
    # Normalize and assign bit-widths
    max_s = max(ls.sensitivity for ls in sensitivities) + 1e-8
    for ls in sensitivities:
        ls.sensitivity /= max_s
        ls.assigned_bits = high_bits if ls.sensitivity > sensitivity_threshold else low_bits
    sensitivities.sort(key=lambda x: x.sensitivity, reverse=True)
    print(f"{'Layer':<50} {'Sensitivity':>12} {'Bits':>6} {'Params':>10}")
    print("-" * 82)
    for ls in sensitivities[:10]:
        print(f"{ls.name:<50} {ls.sensitivity:>12.4f} {ls.assigned_bits:>6} {ls.n_params:>10,}")
    n_high = sum(1 for ls in sensitivities if ls.assigned_bits == high_bits)
    n_low = len(sensitivities) - n_high
    print(f"\nAssigned: {n_high} layers at INT{high_bits}, {n_low} layers at INT{low_bits}")
    return sensitivities

print("Taylor sensitivity: proxy for quantization impact via grad*weight product.")

HAWQ and Hessian-Based Methods

HAWQ (Hessian Aware Quantization, Dong et al., 2019) uses the trace of the Hessian (second-order derivatives) as the sensitivity metric. The Hessian trace captures how curvature of the loss landscape responds to perturbations in each layer's weights. High Hessian trace → high sensitivity → higher bit-width assignment. HAWQ-V2 extends this to mixed-precision between different operators (attention vs FFN) rather than just between layers. Computing the exact Hessian is intractable for LLMs, but the Hutchinson estimator provides an unbiased Monte Carlo estimate of the trace using random Rademacher vectors and Hessian-vector products — computable in O(P) memory with O(P × n_samples) compute.

Evolutionary Search for Bit Assignments

Evolutionary search treats the bit-width assignment as a combinatorial optimization problem. The search space is {2, 4, 8}^N_layers, the fitness function is a weighted sum of perplexity and model size, and the algorithm maintains a population of candidate assignments. Each generation evaluates fitness by running a quantized forward pass at each candidate's bit-widths and computing perplexity on a small validation set. Tournament selection, crossover (swap sub-sequences of layer assignments), and mutation (randomly flip individual layer widths) evolve the population toward Pareto-optimal assignments. Evolutionary search finds better solutions than sensitivity-only methods but requires many evaluations — typically 200–500 forward passes.

import torch
import numpy as np
import random
from dataclasses import dataclass, field
from typing import List, Tuple

@dataclass
class Individual:
    bits: List[int]           # bit-width per layer
    perplexity: float = float('inf')
    model_size_bits: int = 0
    fitness: float = float('inf')

def evolve_bit_assignment(
    n_layers: int,
    bit_choices: List[int],
    fitness_fn,   # callable(bits_list) -> (perplexity, size_bits)
    n_population: int = 20,
    n_generations: int = 30,
    ppl_weight: float = 1.0,
    size_weight: float = 0.3,
    mutation_prob: float = 0.15
) -> Tuple[Individual, List[float]]:
    """Evolutionary search over per-layer bit-width assignments."""
    def make_individual():
        bits = [random.choice(bit_choices) for _ in range(n_layers)]
        return Individual(bits=bits)

    def evaluate(ind: Individual) -> Individual:
        ppl, size = fitness_fn(ind.bits)
        ind.perplexity = ppl
        ind.model_size_bits = size
        # Fitness: weighted sum (lower is better)
        ind.fitness = ppl_weight * ppl + size_weight * (size / 1e9)
        return ind

    def crossover(a: Individual, b: Individual) -> Individual:
        cut = random.randint(1, n_layers - 1)
        child_bits = a.bits[:cut] + b.bits[cut:]
        return Individual(bits=child_bits)

    def mutate(ind: Individual) -> Individual:
        bits = ind.bits.copy()
        for i in range(n_layers):
            if random.random() < mutation_prob:
                bits[i] = random.choice(bit_choices)
        return Individual(bits=bits)

    # Initialize and evaluate population
    population = [evaluate(make_individual()) for _ in range(n_population)]
    best_history = []

    for gen in range(n_generations):
        population.sort(key=lambda x: x.fitness)
        best = population[0]
        best_history.append(best.fitness)
        if gen % 5 == 0:
            avg_bits = np.mean(best.bits)
            print(f"Gen {gen:3d}: best_fitness={best.fitness:.4f} "
                  f"PPL={best.perplexity:.2f} avg_bits={avg_bits:.2f}")
        # Elitism + crossover + mutation
        elite = population[:n_population // 4]
        children = []
        while len(children) < n_population - len(elite):
            a, b = random.sample(elite, 2)
            child = mutate(crossover(a, b))
            children.append(evaluate(child))
        population = elite + children

    population.sort(key=lambda x: x.fitness)
    return population[0], best_history

# Demo with synthetic fitness function
def mock_fitness(bits):
    avg_b = np.mean(bits)
    ppl = 8.5 + max(0, (4.5 - avg_b) * 1.2) + np.random.normal(0, 0.05)
    size = sum(bits) * 1e8
    return ppl, size

best_ind, history = evolve_bit_assignment(
    n_layers=32, bit_choices=[4, 8], fitness_fn=mock_fitness,
    n_population=16, n_generations=20
)
print(f"\nBest assignment: avg={np.mean(best_ind.bits):.2f} bits, PPL={best_ind.perplexity:.2f}")
print(f"Bit widths (first 10 layers): {best_ind.bits[:10]}")

LLM.int8() Mixed-Precision

LLM.int8() (Dettmers et al., 2022) is a mixed-precision quantization scheme built into the bitsandbytes library. It targets the outlier problem in large LLMs: at scales above 6B parameters, a small subset of activation dimensions (typically <0.1%) carry magnitudes 60–100× larger than the median. These outlier features appear consistently in the same hidden dimensions across all tokens and all layers. LLM.int8() detects these outlier columns at calibration time and keeps them in FP16, while quantizing the remaining columns to INT8. The matrix multiplication is decomposed into two matrix multiplications: one FP16 for outlier columns, one INT8 for the rest, and their outputs are summed. This concession to FP16 for <0.1% of values prevents the 2–5 perplexity point degradation that uniform INT8 suffers on large models.

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
import bitsandbytes as bnb

def load_int8_model(
    model_name: str,
    device_map: str = "auto",
    llm_int8_threshold: float = 6.0
) -> tuple:
    """
    Load a model in LLM.int8() mixed-precision.
    Outlier features with magnitude > llm_int8_threshold * layer_std
    are kept in FP16; all other features are quantized to INT8.
    """
    bnb_config = BitsAndBytesConfig(
        load_in_8bit=True,
        llm_int8_threshold=llm_int8_threshold,
        llm_int8_has_fp16_weight=False
    )
    model = AutoModelForCausalLM.from_pretrained(
        model_name,
        quantization_config=bnb_config,
        device_map=device_map,
        torch_dtype=torch.float16
    )
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    # Report memory usage
    if torch.cuda.is_available():
        mem_gb = torch.cuda.memory_allocated() / 1e9
        print(f"GPU memory allocated: {mem_gb:.2f} GB")
    # Count INT8 vs FP16 linear layers
    n_int8 = sum(1 for m in model.modules() if isinstance(m, bnb.nn.Linear8bitLt))
    n_fp16 = sum(1 for m in model.modules() if isinstance(m, nn.Linear)
                 and not isinstance(m, bnb.nn.Linear8bitLt))
    total = sum(p.numel() for p in model.parameters())
    print(f"Linear8bitLt layers: {n_int8}  |  FP16 Linear: {n_fp16}")
    print(f"Total parameters: {total/1e9:.2f}B")
    return model, tokenizer

def benchmark_int8_vs_fp16(model_name: str, prompt: str):
    """Compare memory and throughput: FP16 baseline vs LLM.int8()."""
    import time
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    inputs = tokenizer(prompt, return_tensors="pt")
    for label, load_kwargs in [
        ("FP16",      {"torch_dtype": torch.float16}),
        ("LLM.int8",  {"quantization_config": BitsAndBytesConfig(load_in_8bit=True)}),
    ]:
        model = AutoModelForCausalLM.from_pretrained(model_name, device_map="auto", **load_kwargs)
        inp = {k: v.to(model.device) for k, v in inputs.items()}
        with torch.no_grad():
            t0 = time.perf_counter()
            _ = model.generate(**inp, max_new_tokens=64)
            tps = 64 / (time.perf_counter() - t0)
        mem = torch.cuda.max_memory_allocated() / 1e9
        print(f"{label:<12} mem={mem:.1f} GB  tps={tps:.1f}")
        del model
        torch.cuda.empty_cache()

print("LLM.int8(): keeps outlier features in FP16, quantizes 99.9%+ to INT8.")

LLM.int8() Outlier Handling: LLM.int8() keeps <0.1% of activation outlier features in FP16 while quantizing everything else to INT8 — this small concession prevents the 2–5 PPL spike that uniform INT8 suffers on large models. The outlier dimensions are consistent across tokens and layers, so they can be identified once during calibration and handled with a fixed FP16 path at inference.

AQLM and Vector Quantization

AQLM (Additive Quantization of Language Models, Egiazarian et al., 2024) applies vector quantization to LLM weight matrices, achieving effective 2-bit compression with substantially lower perplexity degradation than scalar INT2 quantization. Instead of quantizing each weight scalar independently, AQLM groups weight columns into vectors of length 8 or 16 and encodes each vector as a sum of M codebook lookups from codebooks of size 2^B. For M=2, B=8: each vector is encoded as two 8-bit codebook indices, giving an effective 2 bits per weight. The codebooks are learned by minimizing layer-wise output reconstruction error. At inference, the encoded indices are dequantized on the fly before the matrix multiplication.

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np

class AQLMQuantizer(nn.Module):
    """
    Simplified AQLM: additive vector quantization of weight columns.
    Encodes each weight column as a sum of M codebook lookups.
    M=2, codebook_size=256 gives ~2 bits/weight for column_dim=8.
    """

    def __init__(self, d_out: int, d_in: int,
                 column_dim: int = 8,
                 n_codebooks: int = 2,
                 codebook_size: int = 256):
        super().__init__()
        assert d_in % column_dim == 0, "d_in must be divisible by column_dim"
        self.d_out = d_out
        self.d_in = d_in
        self.column_dim = column_dim
        self.n_codebooks = n_codebooks
        self.codebook_size = codebook_size
        n_groups = d_in // column_dim  # number of column groups per output row
        # Codebooks: (n_codebooks, codebook_size, column_dim)
        self.codebooks = nn.Parameter(
            torch.randn(n_codebooks, codebook_size, column_dim) * 0.02
        )
        # Indices: (d_out, n_groups, n_codebooks) — stored as int16
        self.register_buffer(
            "indices",
            torch.zeros(d_out, n_groups, n_codebooks, dtype=torch.int16)
        )

    def encode(self, weight: torch.Tensor):
        """Encode a weight matrix into codebook indices (greedy)."""
        d_out, d_in = weight.shape
        n_groups = d_in // self.column_dim
        W = weight.view(d_out, n_groups, self.column_dim)  # (d_out, G, col_dim)
        indices = torch.zeros(d_out, n_groups, self.n_codebooks, dtype=torch.int16)
        for m in range(self.n_codebooks):
            # Residual after previous codebooks
            residual = W.clone()
            if m > 0:
                for prev in range(m):
                    prev_codes = self.codebooks[prev][indices[:, :, prev].long()]  # (d_out, G, col_dim)
                    residual = residual - prev_codes
            # Find nearest codebook entry
            cb = self.codebooks[m]  # (CB, col_dim)
            dists = torch.cdist(
                residual.reshape(-1, self.column_dim),
                cb
            )  # (d_out*G, CB)
            nearest = dists.argmin(dim=-1).reshape(d_out, n_groups).to(torch.int16)
            indices[:, :, m] = nearest
        self.indices.copy_(indices)

    def decode(self) -> torch.Tensor:
        """Reconstruct weight from codebook indices."""
        d_out, n_groups, _ = self.indices.shape
        recon = torch.zeros(d_out, n_groups, self.column_dim,
                            device=self.codebooks.device)
        for m in range(self.n_codebooks):
            recon += self.codebooks[m][self.indices[:, :, m].long()]
        return recon.view(d_out, self.d_in)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        W_hat = self.decode()
        return F.linear(x, W_hat)

# Demo: encode a small linear layer and measure reconstruction error
torch.manual_seed(0)
d_out, d_in = 256, 128
W = torch.randn(d_out, d_in)
quantizer = AQLMQuantizer(d_out=d_out, d_in=d_in, column_dim=8, n_codebooks=2, codebook_size=256)
quantizer.encode(W)
W_hat = quantizer.decode()
rmse = (W_hat - W).pow(2).mean().sqrt().item()
bits_per_weight = (2 * 8) / 8   # 2 codebooks × 8 bits / 8 scalars per group
print(f"AQLM RMSE: {rmse:.5f}  |  Effective bits/weight: {bits_per_weight:.2f}")
print(f"Compression vs FP32: {32 / bits_per_weight:.1f}x")

Automated Mixed Precision

Automated Mixed Precision (AMP) in the NVIDIA/PyTorch sense refers to training-time FP16/BF16 mixed precision — not the inference quantization described above. However, the term is also used for inference-time bit-width automation tools such as Intel Neural Compressor's auto-mixed-precision and Hugging Face Optimum's ORT quantizer, which automatically determine per-layer precision by running sensitivity analysis and applying heuristics. These tools wrap the sensitivity + search pipeline behind a single API call, making mixed-precision quantization accessible without manual layer analysis. For LLMs specifically, bitsandbytes (4-bit NF4 + double quantization) and AutoGPTQ (layer-wise GPTQ + configurable bit mix) are the most practical automated mixed-precision deployment paths.

  • Start with sensitivity analysis (one backward pass) to rank layers before running expensive search algorithms.
  • Protect the embedding layer and LM head — these are almost always the most sensitive and should stay at FP16 or INT8.
  • LLM.int8() threshold=6.0 is a good default; lower it to 4.0 for models above 30B parameters where outlier severity increases.
  • AQLM achieves 2-bit effective compression with far better quality than scalar INT2 — prefer it over Q2_K for GPU inference.
  • Evolutionary search for bit assignments converges in 200–500 evaluations; use n_population=20, n_generations=25 as a starting budget.
  • For practical deployment, bitsandbytes 4-bit NF4 (load_in_4bit=True, bnb_4bit_quant_type='nf4') is the best automated option for 7B–70B models.
  • Mixed INT8/INT4 (sensitive layers at INT8, insensitive at INT4) reduces memory by 60–70% vs FP16 with PPL increase of only 0.1–0.5.

Key Takeaways

  • Uniform quantization applies the same bit-width everywhere; mixed-precision targets resources at the layers that need them.
  • Taylor sensitivity (|grad * weight|) is a cheap and effective proxy for quantization sensitivity — computed in one forward+backward pass.
  • HAWQ uses Hessian trace (via Hutchinson estimator) for a more principled second-order sensitivity ranking.
  • LLM.int8() decomposes matmul into FP16 (outlier columns) + INT8 (remaining columns) — essential for models above 6B parameters.
  • AQLM's vector quantization at 2 effective bits outperforms scalar INT2 by 2–4 perplexity points on 7B models.
  • Evolutionary search is the most flexible assignment method but requires 200+ model evaluations — use sensitivity ranking as initialization.
  • The Pareto-optimal mixed-precision assignment typically uses INT4 for ~70% of layers and INT8 for ~30% of the most sensitive layers.
  • bitsandbytes NF4 with double quantization is the practical default for mixed-precision LLM deployment in 2024–2025.
