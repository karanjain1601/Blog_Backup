Self-Consistency Decoding

  • description: Sampling multiple diverse reasoning paths from an LLM and taking the majority vote answer to improve accuracy over greedy decoding — a form of ensembling over chain-of-thought outputs.
  • topic: deep-learning
  • status: published
  • updated: 2026-07-10

Self-Consistency Decoding

Self-consistency (Wang et al., 2022) is a decoding strategy that replaces greedy or beam-search decoding with a sample-then-vote procedure. Instead of generating a single chain-of-thought reasoning path and reading off its final answer, self-consistency samples N independent reasoning paths at temperature > 0, extracts the final answer from each, and returns the answer supported by the most paths — the majority vote. The intuition is that while there are many ways to reason incorrectly, correct reasoning paths are more likely to converge on the same final answer. Incorrect paths tend to diverge across different errors, so their answers are spread across multiple incorrect values, while the correct answer accumulates votes from the plurality of correct paths. On the GSM8K grade-school math benchmark, greedy chain-of-thought achieves around 57% accuracy with GPT-3 (175B), while self-consistency at N=40 samples reaches 74% — a 17-percentage-point gain with no model fine-tuning, no architectural change, and no additional training data. Self-consistency is the single most reliable accuracy boost available through prompting alone, and it consistently matches or exceeds fine-tuned models on math and reasoning benchmarks when enough samples are drawn.

Overview

The self-consistency algorithm has three steps. First, construct a chain-of-thought prompt using few-shot examples that demonstrate step-by-step reasoning. Second, sample N outputs from the model at temperature T > 0, obtaining N complete reasoning chains each ending with a final answer. Third, extract the final answer from each chain (using regex or a parsing heuristic) and return the most common answer. The method makes two key assumptions: that the model's reasoning process is stochastic enough at moderate temperatures to produce meaningfully diverse paths, and that correct paths agree on the final answer even if they differ in intermediate steps. Both assumptions hold well in practice for arithmetic and commonsense reasoning tasks. Self-consistency is model-agnostic and requires no modification to the model itself — it operates entirely at the decoding layer. The only hyperparameters are N (number of samples), temperature T, and the answer extraction function. In practice, N=20 captures most of the accuracy gain, and N=40 yields diminishing returns. Temperature T=0.7 balances diversity against coherence; lower temperatures reduce diversity and higher temperatures increase noise.

Sampling Diverse Paths

The diversity of sampled reasoning paths is crucial to self-consistency's effectiveness. A batch of N identical or near-identical paths provides no more information than a single greedy path — the majority vote would simply confirm the greedy answer. Meaningful diversity comes from two sources: the model's inherent sampling stochasticity at temperature T > 0, and the multiplicity of valid reasoning approaches for a given problem. For a math problem, one path might use algebraic substitution while another uses unit analysis; both arrive at the same numerical answer. For a commonsense reasoning question, one path might use an analogy while another uses a causal argument. This diversity in reasoning strategy, rather than just random token variation, is what makes the majority vote signal reliable. When paths are diverse but converge on the same answer, that convergence is strong evidence of correctness. When paths diverge on the final answer — half giving 42 and half giving 48 — the majority is correct more often than any individual path, and the vote margin is a rough indicator of confidence.

import re
import asyncio
from collections import Counter
import anthropic

async def self_consistency(question: str, n_samples: int = 20, temperature: float = 0.7) -> dict:
    client = anthropic.AsyncAnthropic()
    prompt = ('Solve step by step and give the final answer clearly.\n\nQuestion: ' + question + '\nAnswer:')
    tasks = [
        client.messages.create(
            model='claude-opus-4-5', max_tokens=512, temperature=temperature,
            messages=[{'role': 'user', 'content': prompt}]
        )
        for _ in range(n_samples)
    ]
    responses = await asyncio.gather(*tasks)
    raw = [r.content[0].text for r in responses]
    extracted = []
    for text in raw:
        m = re.search(r'(?:answer is|=|therefore)[:\s]+\**(-?\d+(?:\.\d+)?)\**', text, re.IGNORECASE)
        if m:
            extracted.append(m.group(1))
    votes = Counter(extracted)
    top = votes.most_common(1)[0] if votes else ('unknown', 0)
    return {'answer': top[0], 'votes': top[1], 'total': len(extracted), 'distribution': dict(votes)}

result = asyncio.run(self_consistency('If a train travels 120 miles in 2 hours, how long to travel 300 miles?'))
print('Answer:', result['answer'], '|', result['votes'], '/', result['total'], 'paths agreed')

The implementation above uses async batch sampling to run all N API calls in parallel, converting the O(N) sequential latency to O(1) wall-clock latency (bounded by the API rate limit and concurrency ceiling). This is important for production use: with sequential sampling, self-consistency at N=20 would take 20x longer than a single call, making it impractical for interactive applications. With async batching, the latency is roughly equivalent to a single call (plus a small coordination overhead), and the cost is N tokens rather than 1. The answer extraction regex handles three common formats: 'the answer is X', '= X', and 'therefore X'. For more complex answer formats (fractions, word answers, multiple-choice letters), the extraction function requires customisation — see the answer extraction code block below.

Majority Vote Aggregation

Majority vote aggregation works by treating each sampled answer as a single vote and returning the plurality winner. For numeric answers, exact string matching is used after normalisation — '42', '42.0', '42.00' should all be treated as the same answer. For symbolic answers (fractions, algebraic expressions), normalisation is more complex and may require a symbolic math library. For multiple-choice answers, the letter or option text is extracted and compared directly. The aggregation function should also handle abstentions — reasoning paths that fail to produce a clearly formatted answer — by excluding them from the vote count rather than treating them as distinct answers. The confidence of the majority vote can be estimated as the vote fraction: if 15/20 paths agree on answer X, the confidence is 0.75. Vote margins below 0.5 (no answer receives more than 50% of valid votes) indicate high uncertainty and should trigger either a fallback to more samples or an explicit 'I'm uncertain' output in user-facing applications.

import re
from fractions import Fraction
from collections import Counter
import anthropic

def extract_answer(cot_text: str):
    patterns = [
        r'(?:the\s+)?(?:final\s+)?answer\s+is[:\s]+\**([^\n.]+)',
        r'(?:therefore|thus|so)[,:\s]+(?:the\s+answer\s+is[:\s]+)?(-?\d+(?:\.\d+)?)',
        r'=\s*(-?\d+(?:\.\d+)?)\s*$',
        r'(?:result|total|sum)[:\s]+(-?\d+(?:\.\d+)?)',
        r'\b([A-E])\b(?:\s*[.)])',
    ]
    for pat in patterns:
        m = re.search(pat, cot_text, re.IGNORECASE | re.MULTILINE)
        if m:
            val = m.group(1).strip()
            try:
                return str(int(float(val))) if '.' in val and float(val) == int(float(val)) else val
            except ValueError:
                return val
    nums = re.findall(r'-?\d+(?:\.\d+)?', cot_text.split('\n')[-1])
    return nums[-1] if nums else None

samples = [
    'Working step by step: 300/120 = 2.5. Therefore 2.5 hours.',
    'Speed = 120/2 = 60 mph. Time = 300/60. The answer is 5 hours.',
    'Rate is 60 miles per hour. 300/60 = 5. = 5',
]
for text in samples:
    print('Answer extracted:', extract_answer(text), '| from:', text[:50])

Robust answer extraction is one of the two engineering challenges in deploying self-consistency (the other being cost management). The extraction function above covers the most common formats but will fail on edge cases: unit-bearing answers ('5 hours' vs '5'), fractions ('3/4' vs '0.75'), and model-specific phrasing ('The result is...' vs 'Therefore...'). For production systems handling diverse question types, a two-stage extraction is more reliable: first, attempt structured parsing with the patterns above; second, if that fails, call the model again with a short prompt asking it to extract just the final answer from the reasoning text. This extraction call is cheap (short output, deterministic at temperature=0) and handles the long tail of formatting variants.

Temperature and Sampling

The sampling temperature T controls the trade-off between diversity and coherence of the sampled reasoning paths. At T=0 (greedy decoding), all N samples are identical — self-consistency degenerates to standard CoT with wasted API calls. At T=1.0, paths are highly diverse but many may be incoherent or produce nonsensical reasoning. In practice, T=0.7 is the most commonly used value for self-consistency and is the value used in the original paper. This temperature produces meaningful variation in reasoning approach while keeping each individual path coherent enough to produce extractable answers. For tasks with high ambiguity in how to approach the problem (commonsense reasoning, multi-step word problems), T=0.7–0.9 works well. For tasks where the reasoning structure is more constrained (arithmetic, formal logic), T=0.5–0.7 is sufficient. Top-p sampling (nucleus sampling) with p=0.95 can be used instead of temperature to limit the tail of low-probability tokens while maintaining diversity, though results are similar to T=0.7 in practice.

import math
import random
from collections import Counter
import anthropic

def simulate_sc_accuracy(correct_rate: float = 0.65,
                          sample_counts: list = None,
                          n_trials: int = 2000) -> dict:
    if sample_counts is None:
        sample_counts = [1, 3, 5, 10, 20, 40]
    results = {}
    for n in sample_counts:
        wins = 0
        for _ in range(n_trials):
            votes: dict = {}
            for _ in range(n):
                ans = 'correct' if random.random() < correct_rate else 'wrong_' + str(random.randint(1, 4))
                votes[ans] = votes.get(ans, 0) + 1
            majority = max(votes, key=lambda k: votes[k])
            wins += (majority == 'correct')
        results[n] = round(wins / n_trials, 4)
    return results

results = simulate_sc_accuracy(correct_rate=0.65)
print('N samples -> Accuracy (GSM8K baseline correct_rate=0.65)')
print('-' * 55)
baseline = results[1]
for n, acc in results.items():
    bar = '#' * int(acc * 40)
    gain = acc - baseline
    print('N={:>3d}  {:.1%}  gain={:>+.1%}  {}'.format(n, acc, gain, bar))
print('Diminishing returns visible after N=20')

Self-Consistency vs Greedy CoT

Self-consistency consistently outperforms greedy chain-of-thought across arithmetic, commonsense, and symbolic reasoning benchmarks. The improvement is largest on tasks where the model's single-path accuracy is moderate (40–70%) — in this regime, diverse paths frequently converge on the correct answer even when no individual path is fully reliable. On tasks where the model already achieves 90%+ accuracy with greedy CoT, self-consistency adds 1–3 percentage points at significant additional cost, which is rarely justified. The performance gap between self-consistency and greedy CoT narrows as model size increases: larger models tend to have more reliable greedy reasoning, leaving less room for the voting ensemble to improve. For GPT-3 (175B) on GSM8K, the gap is 17 points; for GPT-4, the gap narrows to about 5 points because GPT-4's greedy accuracy is already above 90%. Self-consistency also outperforms few-shot prompting without CoT, few-shot CoT with greedy decoding, and zero-shot CoT, establishing it as the strongest prompting-only accuracy technique before fine-tuning is considered.

Self-Consistency Matches Fine-Tuning: Self-consistency at N=20–40 samples often matches fine-tuned models on math and reasoning benchmarks — when you need accuracy without training, it is the most reliable prompting technique available. At N=20, GSM8K accuracy (82.1%) is within 1.7 points of supervised fine-tuning (83.8%) while requiring zero training data, no gradient updates, and no model storage. The break-even point where fine-tuning becomes cheaper than self-consistency is typically around 100K–1M inference calls.

Cost vs Accuracy Tradeoff

Self-consistency's accuracy improvements come at a direct cost multiplier of N on both token consumption and API spend. For a question with a 200-token prompt and a 400-token output, each sample costs approximately 600 tokens. At N=20 samples and Claude's pricing, the cost per question is 20x the single-call cost. For production systems handling thousands of questions per day, this cost must be weighed against the accuracy gain. The break-even analysis is straightforward: if a correct answer has a business value V and an incorrect answer has a cost C, self-consistency is justified when (accuracy_SC - accuracy_CoT) × (V + C) > (N-1) × cost_per_call. For high-stakes domains — medical diagnosis support, financial calculation, legal document analysis — the value-of-correctness is large enough to justify N=20–40 routinely. For lower-stakes applications, N=5 often provides the best cost-accuracy tradeoff, capturing most of the improvement at 5x cost rather than 20x. Adaptive self-consistency — stopping early when one answer accumulates a clear majority — can further reduce average cost while maintaining most of the accuracy gain.

import math
from dataclasses import dataclass
import anthropic

@dataclass
class CostProfile:
    method: str
    n_samples: int
    cost_per_1k_questions: float
    est_accuracy_gsm8k: float

def compute_sc_cost_profile(n_questions: int = 1000,
                             prompt_tokens: int = 200,
                             output_tokens: int = 400,
                             price_in_per_mtok: float = 3.0,
                             price_out_per_mtok: float = 15.0) -> list:
    def cost(n: int) -> float:
        total_in  = n_questions * n * prompt_tokens / 1_000_000
        total_out = n_questions * n * output_tokens / 1_000_000
        return round(total_in * price_in_per_mtok + total_out * price_out_per_mtok, 2)

    scenarios = [
        ('Greedy CoT',  1,  56.9), ('SC N=5',  5, 72.3),
        ('SC N=10',    10, 78.5), ('SC N=20', 20, 82.1), ('SC N=40', 40, 83.4),
    ]
    return [CostProfile(m, n, cost(n), acc) for m, n, acc in scenarios]

profiles = compute_sc_cost_profile()
print(f'{"Method":<14} {"N":>4} {"Cost/1K Q":>12} {"Accuracy":>10} {"Cost/Acc pt":>14}')
for p in profiles:
    cpa = p.cost_per_1k_questions / p.est_accuracy_gsm8k
    print(f'{p.method:<14} {p.n_samples:>4} ${p.cost_per_1k_questions:>10.2f} {p.est_accuracy_gsm8k:>9.1f}% ${cpa:>12.4f}')

The cost analysis reveals the optimal operating points. N=5 offers the best accuracy-per-dollar ratio, capturing 15 points of improvement over greedy CoT at 5x cost. N=10 offers better absolute accuracy with diminishing cost efficiency. N=20 is the recommended default for accuracy-sensitive applications — it reaches the near-plateau of the self-consistency curve at a cost that is still practical for most production workloads. N=40 should only be used when the last fraction of a percent of accuracy matters and cost is unconstrained. For truly cost-constrained settings, an adaptive strategy that starts sampling and stops when one answer has accumulated 60% or more of the votes often achieves N=20 accuracy at an average cost of N=8–12, since many questions have clear majorities early.

When to Use

Self-consistency is the right technique when: (1) the task has a single correct answer that can be extracted from free-text reasoning (arithmetic, factual lookup, multiple-choice), (2) the base model's single-path accuracy is below 85% (leaving meaningful room for ensemble gain), (3) no task-specific fine-tuned model is available, and (4) latency is not the binding constraint. It is not the right technique when: the task produces open-ended text where there is no single correct answer (creative writing, summarisation), the base model already achieves 90%+ accuracy with greedy CoT (marginal gains don't justify 20x cost), or latency is critical (synchronous N=20 sampling takes 20x longer than a single call — always batch asynchronously). Self-consistency also degrades gracefully when the answer distribution is genuinely ambiguous: if no single answer accumulates more than 40% of votes, the question is likely underspecified or beyond the model's knowledge, and the system should escalate to a retrieval augmentation step or human review.

  • Use when: single correct answer exists and can be extracted from free-text reasoning
  • Use when: base model single-path accuracy is 40–85% (most room for ensemble gain)
  • Use when: no fine-tuned model is available and accuracy is critical
  • Avoid when: task produces open-ended text with no extractable single answer
  • Avoid when: greedy CoT already achieves 90%+ accuracy (marginal gain, 20x cost)
  • Always batch N calls asynchronously to avoid 20x latency multiplication
  • Use adaptive early stopping (60% vote majority) to cut average cost by 30–50%

Key Takeaways

Self-consistency is the single most reliable prompting-only accuracy improvement technique available. By sampling N independent reasoning paths and taking the majority vote answer, it achieves accuracy gains of 10–20 percentage points over greedy chain-of-thought on arithmetic and reasoning tasks, often matching supervised fine-tuning at N=20 samples. The implementation requires three components: a chain-of-thought prompt, an async batch sampler, and a robust answer extraction function. The cost is N times the single-call cost, making cost management through adaptive stopping and sample-count optimisation an important engineering concern. Start with N=5 for cost-sensitive applications and escalate to N=20 when accuracy is paramount. Always run samples asynchronously to avoid latency multiplication. The technique is model-agnostic, requires no training or architectural changes, and works across arithmetic, commonsense reasoning, and formal logic tasks.

  • Sample N independent CoT paths at temperature=0.7, not greedy temperature=0
  • Extract the final answer from each path using regex or a second short LLM call
  • Return the plurality answer; confidence is vote fraction (high >0.6, uncertain <0.4)
  • N=5 gives the best accuracy-per-dollar; N=20 is the recommended default for accuracy-critical tasks
  • Always batch N calls asynchronously to keep latency equivalent to a single call
  • Self-consistency at N=20 matches supervised fine-tuning on GSM8K, SVAMP, and AQuA
  • Adaptive early stopping: halt sampling when one answer reaches 60% of votes
